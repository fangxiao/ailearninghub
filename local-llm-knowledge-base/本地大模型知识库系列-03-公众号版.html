构建本地知识库

从文档到智能问答

本地大模型知识库系列第03篇 | RAG实战

前两篇我们讲了为什么要搭建本地知识库，以及如何安装Ollama环境。今天终于到了最核心的环节——构建一个完整的本地知识库系统。

RAG（Retrieval-Augmented Generation）是构建知识库的核心技术。简单来说，就是把你的文档变成机器能理解的"知识"，然后让大模型基于这些知识来回答问题。

01 知识库架构总览

一个完整的本地知识库系统包含四层架构：

文档层：存放原始文档，支持PDF、Word、Markdown、网页等多种格式；
向量层：使用Embedding模型将文本转换为向量，并存入向量数据库；
检索层：根据用户问题进行语义检索和关键词检索；
应用层：基于检索结果，让LLM生成最终回答。

02 第一步：文档加载与分割

首先，我们需要把文档加载到系统中。但大模型一次只能处理有限的文本，所以需要把长篇文档分割成小块。

常用的分割方式有三种：按字符数分割、按段落分割、按章节分割。其中按段落分割能较好地保持语义完整性。

bash
pip install langchain chromadb sentence-transformers pypdf
python
from langchain.document_loaders import PyPDFLoader from langchain.text_splitter import RecursiveCharacterTextSplitter # 加载PDF文档 loader = PyPDFLoader('your_document.pdf') documents = loader.load() # 分割文本 text_splitter = RecursiveCharacterTextSplitter( chunk_size=500, chunk_overlap=50, length_function=len, ) chunks = text_splitter.split_documents(documents) print(f"分割成 {len(chunks)} 个片段")

💡 用简单的话解释复杂概念

chunk_size=500表示每个片段最多500个字符，chunk_overlap=50表示相邻片段有50个字符的重叠，这样能确保上下文不会被完全切断。

03 第二步：向量化与存储

文本分割完成后，需要将每个片段转换为向量。这个过程就像是给每段文字"拍照"，把文字变成一串数字，机器可以通过比较这些数字来判断语义相似度。

向量化完成后，需要选择一个向量数据库来存储这些向量。以下是几种常见的选择：

对于本地部署，Chroma是最佳选择——轻量级、无需额外部署、API友好。下面是完整的向量化和存储代码：

python
from langchain.vectorstores import Chroma from langchain.embeddings import HuggingFaceEmbeddings # 初始化Embedding模型 embeddings = HuggingFaceEmbeddings( model_name="all-MiniLM-L6-v2" ) # 创建向量数据库 vector_store = Chroma.from_documents( documents=chunks, embedding=embeddings, persist_directory="./chroma_db" ) # 持久化到磁盘 vector_store.persist() print("向量数据库创建完成！")

04 第三步：构建RAG问答系统

现在，文档已经变成了可检索的知识。接下来，我们需要构建一个完整的问答系统，让用户可以基于自己的文档提问。

python
from langchain.chains import RetrievalQA from langchain.llms import Ollama # 初始化Ollama LLM llm = Ollama(model="llama3:8b") # 加载向量数据库 vector_store = Chroma.persist_directory( persist_directory="./chroma_db", embedding_function=embeddings ) # 创建检索器 retriever = vector_store.as_retriever( search_kwargs={"k": 3} ) # 创建RAG问答链 qa_chain = RetrievalQA.from_chain_type( llm=llm, chain_type="stuff", retriever=retriever, return_source_documents=True, ) # 提问 query = "请解释文档中的核心概念" result = qa_chain({"query": query}) print("回答:") print(result["result"])

进阶 优化检索效果

想要更好的检索效果，可以尝试以下优化技巧：

优化方法 说明
调整chunk_size 根据文档类型调整，技术文档可以适当增大
使用更好的Embedding模型 尝试bge-base-zh等中文优化模型
调整检索数量k k值越大，检索结果越全面但可能引入噪声
使用不同的chain_type map_reduce适合长文档，refine适合需要迭代优化的场景

⚠️ 常见问题

1. Embedding模型下载慢：可以使用国内镜像或提前下载模型文件

2. 向量数据库占用空间大：考虑使用量化后的模型或清理临时文件

3. 检索结果不准确：尝试调整chunk_size、更换Embedding模型或增加k值

4. 中文支持不好：使用bge-base-zh或text2vec-large-chinese等中文模型
