最小可行Agent

上一期我们说了Agent的核心循环：感知、思考、行动、反思。(见OpenClaw原理篇11)

光说不练假把式。这一期，我们写一个能跑的系统。代码不到100行，但该有的循环都有。

💡 先跑起来：你看10篇原理文章，不如亲手写一个能跑的系统有感觉。

1最简版本：30行代码

先去掉所有花哨的东西，就保留最核心的循环：

import openai

class SimpleAgent:
    def __init__(self):
        self.messages = []

    def run(self, user_input):
        # 感知：把用户输入加到对话历史
        self.messages.append({"role": "user", "content": user_input})

        # 思考+行动：调用大模型
        response = openai.ChatCompletion.create(
            model="gpt-4",
            messages=self.messages
        )

        # 反思：从响应中提取助手回复
        assistant_msg = response.choices[0].message
        self.messages.append(assistant_msg)

        return assistant_msg["content"]

就这么点代码。一个类，三个方法，加起来不到30行。用法：

agent = SimpleAgent()
print(agent.run("你好"))
print(agent.run("帮我写一首诗"))

这个版本能跑，但它只是个对话机器人。Agent和普通聊天机器人的区别，在于那个"循环"。(核心循环详解)

2进阶版本：加工具调用

真正的Agent会自己决定要不要调用工具。(参考OpenClaw进阶篇09)

pythonclass SimpleAgentWithTools:
    def __init__(self):
        self.messages = []
        self.tools = {}

    def register_tool(self, name, func):
        self.tools[name] = func

    def run(self, user_input, max_turns=5):
        self.messages.append({"role": "user", "content": user_input})

        for _  in range(max_turns):
            response = openai.ChatCompletion.create(
                model="gpt-4",
                messages=self.messages,
                tools=self.tools
            )

            message = response.choices[0].message

            if message.get("tool_calls"):
                for call  in message["tool_calls"]:
                    tool_name = call["function"]["name"]
                    args = json.loads(call["function"]["arguments"])
                    result = self.tools[tool_name](**args)
                    self.messages.append({
                        "role": "tool",
                        "tool_call_id": call["id"],
                        "content": str(result)
                    })
            else:
                self.messages.append(message)
                return message["content"]

        return "已达到最大轮次"

新增三个关键点：

  • register_tool — 注册工具，让Agent知道有哪些武器可用
  • max_turns — 限制最大轮次，防止无限循环
  • tool_calls — 检测模型是否想调用工具 (参考AI Coding第28篇)

举个例子。用户问"帮我算 (12 + 8) * 3"：

  • 1. Agent想了想，发现要调用calculator
  • 2. 调用工具，算出60
  • 3. 把结果返回给用户

💡 这就是Agent的核心能力：不只是聊天，而是能真的帮你做事。

3还缺什么

这个最小版本能跑，但生产环境还差得远：

❌ 记忆系统 — 每次对话从零开始，Agent记不住之前说过什么
   (见OpenClaw原理篇12)
❌ 反思机制 — 没有判断结果对不对的能力
❌ 错误处理 — 工具调用失败了怎么办
❌ 流式输出 — 等全部生成完再返回，用户体验差

这个系列的后续文章，会一个一个把这些补上。先记住这个框架，后面的东西都好说。

感知：用户输入到结构化意图

感知是什么？你跟Agent说"帮我订明天去上海的机票"，Agent得先理解：

  • 用户想要什么？→ 订机票
  • 出发地？→ 没说，可能是当前位置
  • 目的地？→ 上海

这个理解的过程，就是感知。把用户的自然语言，变成机器能理解的结构化数据。

💡 感知是第一步：没有这一步，Agent就是个复读机——你说啥它重复啥，不知道你要什么。

1意图识别

用户说了一句话，Agent首先要判断：用户想要做什么？这个过程叫意图识别（Intent Detection）。(参考AI Coding第28篇)

pythonINTENTS = ["订机票", "查天气", "写代码", "搜索信息", "其他"]

def detect_intent(user_input):
    prompt = f"用户说："{user_input}"\n这个用户的意图是什么？" 

    response = openai.ChatCompletion.create(
        model="gpt-4",
        messages=[{"role": "user", "content": prompt}]
    )

    return response.choices[0].message["content"]

⚠️ 但这个方法太慢了——每次都要调一次大模型。实际项目中，可以用规则匹配或者小模型来做意图识别，把大模型留到真正需要的地方。

2实体提取

判断了意图之后，还要提取关键信息。比如用户说"帮我订后天北京到上海的机票"：

  • 时间 → 后天
  • 出发地 → 北京
  • 目的地 → 上海

这个过程叫实体提取（Entity Extraction）。代码：

pythondef extract_entities(user_input):
    prompt = f"""从以下用户输入中提取关键信息：

用户输入："{user_input}"

提取以下信息（如果没有则填"未知"）：
- 时间
- 出发地
- 目的地
- 人数

请用JSON格式返回"""

    response = openai.ChatCompletion.create(
        model="gpt-4",
        messages=[{"role": "user", "content": prompt}]
    )

    import json
    return json.loads(response.choices[0].message["content"])

3整合：感知的完整实现

pythondef perceive(self, user_input):
    # 1. 识别意图
    intent = self.detect_intent(user_input)

    # 2. 提取实体
    entities = self.extract_entities(user_input)

    # 3. 组合成结构化上下文
    return {
        "intent": intent,
        "entities": entities,
        "raw_input": user_input
    }

💡 感知做好了：后面的思考和行动就轻松了。Agent知道你要什么，才能决定怎么做。
