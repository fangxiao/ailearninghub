Bot数据模型设计

进入Bot核心篇。这一篇，我们来聊一个看似简单、实则极其重要的问题：Bot的数据模型应该怎么设计？

很多人觉得Bot不就是"名字+描述+Prompt"吗？但当你真正去做生产级应用，会发现配置远比想象复杂——版本管理、变量插值、插件关联、工作流绑定……每一个都是坑。

💡 核心观点：Bot数据模型是整个myAgent的核心。一切后续功能——插件、工作流、记忆——都建立在Bot模型之上。模型设计不好，后续扩展全是噩梦。

1Bot实体：最基础的配置

先来看Bot的最基础实体：

python# backend/models/bot.py
from sqlmodel import SQLModel, Field
from typing import Optional
from datetime import datetime

class Bot(SQLModel, table=True):
    __tablename__ = "bots"

    id: str = Field(primary_key=True, default=lambda: uuid.uuid4().hex)
    name: str = Field(max_length=100)          # Bot名称
    description: str = Field(default="")                # 描述
    avatar: Optional[str] = None                 # 头像URL

    model: str = Field(default="gpt-4")          # 使用的模型
    temperature: float = Field(default=0.7)   # 温度参数
    max_tokens: int = Field(default=2000)      # 最大token

    system_prompt: str = Field(default="")         # 系统提示词
    prompt_config: dict = Field(default=dict)  # Prompt变量配置

    plugin_ids: list[str] = Field(default=list)  # 启用的插件
    workflow_id: Optional[str] = None        # 关联的工作流

    status: str = Field(default="draft")       # draft | published
    version: int = Field(default=1)             # 当前版本号

    owner_id: str = Field(index=True)           # 拥有者
    tenant_id: str = Field(index=True)          # 租户ID

    created_at: datetime = Field(default=datetime.utcnow)
    updated_at: datetime = Field(default=datetime.utcnow)

这个模型有几个关键设计：

  • prompt_config——这是个JSON字段，存Prompt里的变量配置。比如Prompt里有个{"variable": "name", "default": "用户", "type": "string"}，运行时会被替换
  • plugin_ids——Bot启用的插件列表，不是直接存储插件对象，而是存ID，便于解耦
  • status——draft/published状态机，支持先编辑再发布

2Bot版本：支持灰度发布和回滚

生产级Bot必须有版本控制。为什么？

  • 你发布了一个新版本，发现有bug，需要快速回滚
  • 你想灰度发布，先让10%用户用新版本
  • 你需要对比两个版本的效果差异
pythonclass BotVersion(SQLModel, table=True):
    __tablename__ = "bot_versions"

    id: str = Field(primary_key=True, default=lambda: uuid.uuid4().hex)
    bot_id: str = Field(foreign_key="bots.id", index=True)
    version: int = Field(index=True)

    # 快照：发布时的完整配置
    config_snapshot: dict = Field()

    # 发布信息
    status: str = Field(default="draft")  # draft | published | deprecated
    rollout_percent: int = Field(default=100)  # 灰度发布比例

    changelog: str = Field(default="")          # 变更说明
    published_at: Optional[datetime] = None
    published_by: Optional[str] = None

核心设计：config_snapshot存发布时刻的完整配置快照。这样回滚时直接用快照恢复，不需要计算diff。

3Prompt配置Schema：让Prompt可编程化

上一节提到prompt_config，这里详细说说。

简单Bot只有一个system_prompt就够了，但企业级Bot通常需要变量：

text# 一个客服Bot的Prompt
你是一个{company_name}的客服助手。
公司产品：{product_list}
服务时间：{service_hours}
当前用户：{user_name}

# {xxx}都是变量，需要在prompt_config里定义

prompt_config的Schema设计：

python# prompt_config的JSON结构
prompt_config = {
    "variables": [
        {
            "name": "company_name",
            "type": "string",
            "default": "某公司",
            "description": "公司名称",
        },
        {
            "name": "product_list",
            "type": "string",
            "source": "knowledge_base",      # 从知识库动态获取
            "kb_id": "kb_xxx",
        }
    ]
}

这种设计的优势：Prompt模板和具体值分离。同一个Prompt模板，可以给不同租户使用，只需要替换变量值。

4对话会话：多轮对话的存储

Bot的另一个核心模型是会话（Session）和消息（Message）：

pythonclass Conversation(SQLModel, table=True):
    __tablename__ = "conversations"

    id: str = Field(primary_key=True)
    bot_id: str = Field(foreign_key="bots.id", index=True)
    user_id: str = Field(index=True)
    bot_version_id: str = Field(index=True)     # 使用哪个版本

    # 状态
    status: str = Field(default="active")  # active | closed
    
    # Token统计（用于计费）
    total_tokens: int = Field(default=0)
    
    created_at: datetime = Field(default=datetime.utcnow)
    updated_at: datetime = Field(default=datetime.utcnow)

class Message(SQLModel, table=True):
    __tablename__ = "messages"

    id: str = Field(primary_key=True)
    conversation_id: str = Field(foreign_key="conversations.id", index=True)

    role: str  # user | assistant | system | tool
    content: str
    
    # Token统计
    tokens: int = Field(default=0)
    
    # 工具调用信息（如果role=tool）
    tool_call_id: Optional[str] = None
    tool_name: Optional[str] = None
    
    created_at: datetime = Field(default=datetime.utcnow)

几个关键设计点：

  • bot_version_id——记录对话使用的是哪个Bot版本，方便追溯和计费
  • total_tokens——会话级别的Token统计，用于计费和监控
  • tool_call_id/tool_name——支持工具调用的完整链路追溯

💡 总结：Bot数据模型是myAgent的核心。Bot模型存配置，BotVersion存快照支持回滚，prompt_config支持变量插值，Conversation/Message支持多轮对话。模型设计要考虑：可版本化、可变量化、可追溯。
