插件架构设计

进入插件系统篇。插件系统是myAgent最强大的能力之一——让Bot可以像人一样"学会"各种新技能。

很多人用过OpenClaw的插件，觉得很强大。但它背后是怎么实现的？这一篇，我们来实现一个灵活的插件框架。(参考Agent开发系列13：Tool接口设计)

💡 核心观点：插件系统的核心是"接口抽象"——只要符合接口，任何人都能开发插件。好的插件系统，应该是"你只管写插件逻辑，剩下的交给框架"。

1插件接口：标准化是解耦的关键

先定义插件接口。(Tool接口设计详见Agent开发系列13)

python# backend/plugins/base.py
from abc import ABC, abstractmethod
from typing import Any, Dict
from pydantic import BaseModel

class ToolParameter(BaseModel):
    name: str
    type: str
    description: str
    required: bool = True
    default: Any = None

class ToolDefinition(BaseModel):
    name: str
    description: str
    parameters: list[ToolParameter] = []

class ToolResult(BaseModel):
    success: bool
    result: Any = None
    error: str = None

class BaseTool(ABC):
    # 插件基类，所有插件必须继承这个类

    @property
    @abstractmethod
    def definition(self) -> ToolDefinition:
        # 返回插件定义，供LLM理解插件能力
        pass

    @abstractmethod
    async def execute(self, **kwargs) -> ToolResult:
        # 执行插件逻辑
        pass

核心设计：definition告诉LLM这个插件有什么用，execute才是真正的逻辑。

2插件注册：动态发现与加载

插件写好了，怎么让系统知道？用插件注册表。

python# backend/plugins/registry.py
class ToolRegistry:
    _tools: Dict[str, BaseTool] = {}

    @classmethod
    def register(cls, tool: BaseTool):
        definition = tool.definition
        cls._tools[definition.name] = tool

    @classmethod
    def get(cls, name: str) -> BaseTool | None:
        return cls._tools.get(name)

    @classmethod
    def list_all(cls) -> List[ToolDefinition]:
        return [tool.definition for tool in cls._tools.values()]

# 用装饰器注册插件
def register_tool(tool_class):
    ToolRegistry.register(tool_class())
    return tool_class

使用装饰器，插件开发者只需要一行代码就能注册：

python# backend/plugins/search.py
from .base import BaseTool, ToolDefinition, ToolResult

# 一行装饰器，自动注册
@register_tool
class SearchTool(BaseTool):

    @property
    def definition(self):
        return ToolDefinition(
            name="search",
            description="搜索互联网获取信息",
            parameters=[{
                "name": "query",
                "type": "string",
                "description": "搜索关键词"
            }]
        )

    async def execute(self, query: str) -> ToolResult:
        try:
            results = await search_api.search(query)
            return ToolResult(success=True, result=results)
        except Exception as e:
            return ToolResult(success=False, error=str(e))

3插件生命周期

每个插件都有自己的生命周期：

pythonclass BaseTool(ABC):
    # 可选：插件初始化
    async def on_load(self):
        "插件加载时调用，可以做初始化操作"
        pass

    # 可选：插件卸载前调用
    async def on_unload(self):
        "插件卸载时调用，可以做清理操作"
        pass

    # 可选：每次执行前调用
    async def before_execute(self, **kwargs):
        "执行前校验，比如检查API配额"
        pass

    # 可选：每次执行后调用
    async def after_execute(self, result: ToolResult):
        "执行后处理，比如记录日志"
        pass

生命周期钩子让插件可以做一些横切关注点——比如日志、性能监控、错误追踪。

4Bot与插件的绑定

Bot启用哪些插件？在Bot模型里定义。(详见myAgent开发系列05：Bot数据模型)

python# Bot启用哪些插件，由plugin_ids决定
class BotExecutor:

    @property
    def available_tools(self):
        bot = self.bot
        return [
            ToolRegistry.get(plugin_id)
            for plugin_id in bot.plugin_ids
            if ToolRegistry.get(plugin_id)
        ]

这就是解耦的好处：Bot只存储插件ID，具体插件实现在运行时才绑定。改插件实现不需要改Bot配置。

💡 总结：插件系统的核心是接口抽象和动态注册。BaseTool定义接口规范，ToolRegistry负责插件注册，Bot通过plugin_ids引用插件。生命周期钩子让插件可以处理横切关注点。
