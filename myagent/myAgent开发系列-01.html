很多人用Coze/扣子、Dify，觉得好用。但好用背后的架构是怎么设计的？大多数文章只告诉你"怎么用"，没人告诉你"为什么这么设计"。(参考OpenClaw进阶篇13)

💡 核心观点：不要急着写代码。在动手之前，先问自己：我真的准备好了吗？这一篇，我们先聊聊开发myAgent之前必须掌握的知识点，以及为什么这些知识比写代码更重要。

1myAgent是什么？为什么要做这个项目？

myAgent = Self + Claw。寓意：自我定制、自我进化的智能体平台。

OpenClaw（龙虾）是一个开源的AI Agent开发平台，功能强大，但部署门槛高、定制困难。myAgent的目标是：做一个更轻量、更易定制、更适合学习的版本。

对比项OpenClawmyAgent
定位企业级平台学习+轻量定制
部署Docker/K8s本地即可运行
复杂度高中
学习曲线陡峭平缓
代码量数十万行几千行（核心）

myAgent不是要替代OpenClaw，而是提供一个更容易上手的学习版本。学完之后，你再去研究OpenClaw的完整代码，会发现一切都是相通的。

3技术栈选择：为什么用这些技术？

很多人问我：为什么选Next.js + Python？为什么不选XXX？

技术选型的核心原则是：够用就行，不要过度设计。

text# myAgent技术栈
## 前端
Next.js 14 (App Router)     # React SSR框架，现代前端标配
TypeScript                 # 类型安全，减少bug

React Flow                 # 工作流可视化

## 后端
Python 3.11+               # AI领域首选，生态丰富
FastAPI                    # 异步高性能，类型提示好
PostgreSQL                 # 关系数据存储
Redis                      # Session和缓存
pgvector                   # 向量检索（选pgvector因为一体化）

为什么不选XXX？

  • 为什么不选Django？→ 太重，Agent场景不需要ORM的复杂功能
  • 为什么不选Node.js后端？→ Python在AI领域生态碾压
  • 为什么不选MongoDB？→ 结构化数据用PostgreSQL更稳
  • 为什么不选Pinecone？→ pgvector够用，没必要多一个外部服务

4最小知识集：Agent核心循环

如果你的时间只够学一个知识点，那必须是Agent核心循环。(参考OpenClaw原理篇11)

python# Agent核心循环 - 这是一切的基础
def agent_loop(agent, user_input):
    context = []

    while True:
        # 1. 思考：基于上下文，让LLM决定下一步
        response = llm.chat(context + [user_input])

        # 2. 如果是最终回答，结束
        if response.is_final:
            return response.content

        # 3. 如果是工具调用，执行并把结果加回上下文
        for tool in response.tool_calls:
            result = execute_tool(tool)
            context.append(f"Tool {tool.name} returned: {result}")

这个循环不理解清楚，后面的代码你根本看不懂。很多人觉得"不就是调API吗"，但真正的问题是：什么时候该调用工具？如何让多轮对话保持连贯？遇到失败怎么办？

5项目结构：一上来就要设计好

我见过太多"先写再说"的项目，最后代码成一团乱麻。myAgent的项目结构，在第一天就定好了。

text# myAgent项目结构
selfclaw/
├── frontend/              # Next.js前端
│   ├── app/
│   ├── components/
│   └── ...
├── backend/              # Python后端
│   ├── api/
│   ├── core/            # Agent核心循环
│   ├── plugins/         # 插件系统
│   └── ...
├── shared/              # 共享类型定义
└── docker-compose.yml   # 一键启动

核心原则：前后端分离，共享类型定义。这样前端改需求不会波及后端，后端升级不会搞挂前端。
