Bot版本控制与发布

上一节讲了Bot数据模型和Prompt工程。这一节，讲一个生产级Bot必须具备的能力：版本控制和发布管理。

很多人觉得"改完Prompt直接发布就行了"。但生产环境中，你可能需要：凌晨三点发现线上Bot有问题要回滚；想让10%用户先试试新版本；想对比新旧两个版本的效果差异。

没有版本控制的Bot，就是一颗定时炸弹。

💡 核心观点：版本控制不只是"记录改了啥"，而是提供"回到过去"和"选择未来"的能力。Draft/Published状态机 + 灰度发布，是生产级Bot的标配。

1状态机：Draft和Published

Bot的基本状态只有两个：

Figure: Bot State Machine - Draft and Published states

  • Draft（草稿）——可以随便改，不影响线上用户
  • Published（已发布）——正在服务用户的版本，不能随便改
python# backend/services/bot_service.py
class BotService:

    def create_bot(self, bot_data: BotCreate) -> Bot:
        # 新创建的Bot默认是Draft
        bot = Bot(
            name=bot_data.name,
            description=bot_data.description,
            status="draft",  # 默认草稿
            version=1,
            owner_id=bot_data.owner_id,
            tenant_id=bot_data.tenant_id,
        )
        db.add(bot)
        return bot

    def publish_bot(self, bot_id: str, changelog: str = "") -> BotVersion:
        bot = self.get_bot(bot_id)
        if bot.status == "published":
            # 已经发布的Bot，需要创建新版本
            return self._create_new_version(bot, changelog)
        else:
            # 草稿状态，直接发布第一个版本
            return self._publish_first_version(bot, changelog)

2版本快照：发布即存档

发布时最重要的操作是创建版本快照——把当前配置完整保存下来。

pythondef _create_version_snapshot(bot: Bot) -> BotVersion:
    # 创建配置快照
    snapshot = {
        "name": bot.name,
        "model": bot.model,
        "temperature": bot.temperature,
        "max_tokens": bot.max_tokens,
        "system_prompt": bot.system_prompt,
        "prompt_config": bot.prompt_config,
        "plugin_ids": bot.plugin_ids,
        "workflow_id": bot.workflow_id,
    }

    version = BotVersion(
        bot_id=bot.id,
        version=bot.version,
        config_snapshot=snapshot,
        status="published",
        published_at=datetime.utcnow(),
    )
    db.add(version)

    # 更新Bot状态
    bot.status = "published"
    bot.published_version_id = version.id

    return version

快照的好处是：即使Bot配置被改的面目全非，也能一键回到任何一个历史版本。

3回滚：让事故损失最小化

版本控制的核心价值之一是回滚能力。

pythondef rollback_bot(self, bot_id: str, target_version: int) -> Bot:
    bot = self.get_bot(bot_id)

    # 查找目标版本
    version = db.query(BotVersion).filter(
        BotVersion.bot_id == bot_id,
        BotVersion.version == target_version
    ).first()

    if not version:
        raise ValueError(f"Version {target_version} not found")

    # 从快照恢复配置
    snapshot = version.config_snapshot
    bot.model = snapshot["model"]
    bot.temperature = snapshot["temperature"]
    bot.system_prompt = snapshot["system_prompt"]
    # ... 其他字段

    # 创建新的回滚版本记录
    bot.version += 1
    self._create_version_snapshot(bot)

    return bot

回滚操作的关键是：不修改历史快照，而是基于快照创建新版本。这样任何版本都可以追溯。

4灰度发布：小心驶得万年船

生产级发布不只是"全量"或"不回滚"，还有灰度发布。

pythondef publish_with_rollout(self, bot_id: str, rollout_percent: int = 10):
    # rollout_percent: 0-100，0就是不发布，100就是全量
    if rollout_percent == 0:
        return  # 不发布

    bot = self.get_bot(bot_id)
    new_version = self._create_new_version(bot)

    # 设置灰度比例
    new_version.rollout_percent = rollout_percent
    new_version.status = "published"

    if rollout_percent == 100:
        # 全量发布，把旧版本标记为deprecated
        self._deprecate_old_versions(bot.id, new_version.version)
    else:
        # 灰度发布，新旧版本共存
        pass

灰度发布时，需要根据用户ID做路由：

pythondef get_bot_version_for_user(bot_id: str, user_id: str) -> BotVersion:
    versions = db.query(BotVersion).filter(
        BotVersion.bot_id == bot_id,
        BotVersion.status == "published"
    ).all()

    # 根据user_id的hash决定用哪个版本
    user_hash = hash(user_id) % 100

    for v in versions:
        if v.rollout_percent > user_hash:
            return v

    # 默认返回最新全量版本
    return self._get_latest_full_version(versions)

灰度发布的核心是"用户无感知"——同一个Bot，对不同用户可能返回不同版本。

💡 总结：Bot版本控制包含状态机（Draft/Published）、版本快照、回滚能力、灰度发布。生产级Bot必须具备这些能力，才能应对凌晨三点的线上事故。
