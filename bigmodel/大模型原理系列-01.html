大模型原理系列 01

系列四 从RNN到Transformer，模型是怎么"学会"理解语言的

1从系列三的一个问题开始

在系列三的第9篇（章17-18）· Agent执行引擎里，我们讲了一个请求进来后，Agent是怎么调度的：接收消息、加载记忆、调用工具、生成回复。

但有一个问题我们没有深入讲：模型是怎么"生成"每一个字的？

当你对Agent说"你好"，模型是如何决定下一个字是"啊"还是"呀"？

要回答这个问题，就要从Transformer架构说起。

2RNN时代：串行处理的困境

在Transformer出现之前，主流的序列处理模型是RNN（循环神经网络）。

RNN的工作方式很简单：处理一句话时，它是一个字一个字的处理，就像工厂流水线：

  • 读到"你"，记住"你"的信息
  • 读到"好"，结合之前的"你"，生成"好"的信息
  • 读到"啊"，结合之前的"你"和"好"，生成"啊"的信息

图1：RNN串行处理——必须等待前一个字完成才能处理下一个

问题在于：RNN是串行处理的。"你"和"好"的位置隔得越远，模型在生成"啊"的时候就越难记住"你"的信息。

这就是为什么早期的聊天机器人经常"前言不搭后语"——模型确实记住了，但记不住太远的东西。

还有一个致命问题：无法并行计算。处理一句话需要等前一个字处理完，效率极低。

3Attention机制：让每个字都看到所有字

2017年，Google发表了一篇划时代的论文《Attention Is All You Need》，提出了Transformer架构。

Transformer的核心思想是：不再串行处理，而是并行处理——让每个字同时"看到"整句话。

怎么做到的呢？靠的是Self-Attention（自注意力机制）。

Self-Attention的工作方式是：当你看到一句话时，不是简单地记住每个字，而是计算每个字和其他字之间的关系。

图2：Self-Attention并行处理——所有字同时参与计算

# Self-Attention的核心计算（伪代码） # 输入：每个字的"表示"（embedding） # 输出：每个字的新表示，综合考虑了与其他字的关系 # 1. 为每个字生成三个向量：Query(查询)、Key(键)、Value(值) query = word_embedding * Wq # 我要找什么 key = word_embedding * Wk # 我是什么 value = word_embedding * Wv # 我的内容是什么 # 2. 计算注意力分数：当前字对所有字的"关注程度" attention_scores = softmax(query @ key.T / sqrt(d_k)) # 3. 加权求和：得到融合了上下文的新表示 output = attention_scores @ value

简单理解：Self-Attention就是在问——"这句话里，每个字应该多大程度地参考其他字来理解自己？"

比如在"小明喜欢小红"这句话里：

  • "喜欢"这个词，会高度关注"小明"和"小红"（谁喜欢谁）
  • "小明"会关注"喜欢"和"小红"（知道自己在喜欢）
  • "小红"会关注"小明"和"喜欢"（知道被谁喜欢）

这种"同时看到"的能力，解决了RNN的长期依赖问题。

4Position Encoding：解决"顺序"问题

但Attention有一个问题：它本身不考虑位置信息。

"小明喜欢小红"和"小红喜欢小明"，在Self-Attention看来是一样的——因为它只看词与词之间的关系，不看谁在谁前面。

Transformer的解决方案是Position Encoding（位置编码）：给每个位置一个独特的"位置向量"，加到词的表示上。

# 位置编码公式（简化版） PE(pos, 2i) = sin(pos / 10000^(2i/d_model)) PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model)) # pos是位置，i是维度，d_model是模型维度

为什么要用sin/cos函数？因为这样可以让模型很容易学到"相对位置"——比如"在...后面"这样的关系。

加上位置编码后，"小明喜欢小红"和"小红喜欢小明"就变成了不同的输入。

5Encoder和Decoder：GPT和BERT的区别

完整的Transformer包含两个部分：

  • Encoder（编码器）：把输入序列变成一个"理解"——适合完形填空、分类任务
  • Decoder（解码器）：基于Encoder的"理解"和已经生成的内容，生成下一个字——适合翻译、对话

BERT是纯Encoder架构——它看完整个句子后，理解了含义，适合做"填空题"（比如判断一句话是正面还是负面）。

GPT是纯Decoder架构——它的任务是逐字生成，每次生成一个字，然后把新生成的字加入输入，再生成下一个字。

这就是为什么GPT是"生成式"的，而BERT不是。

所以当你和Agent对话时，模型实际上在做这样的循环：

图3：GPT自回归生成——每次生成一个字，加入输入后继续生成

# GPT生成一句话的简化过程 input = "你好" # 你的输入 for i in range(max_length): # 1. 模型看整个输入（包括之前生成的字） output = transformer(input) # 2. 选出概率最高的下一个字 next_word = output[-1].argmax() # 3. 把新字加入输入 input = input + next_word # 4. 如果生成了结束符，就停下来 if next_word == "": break

6回到系列三：它和Agent执行引擎的关系

现在我们回头看系列三的内容，能更好地理解Agent是怎么工作的。

执行引擎（17篇）调度模型生成回复，但生成的过程是由Transformer完成的。

记忆系统（8、19篇）把历史对话作为输入传给模型，而Transformer能同时处理整段上下文，这就是Attention的功劳。

工具调用（13篇）时，模型需要理解"现在需要调用一个计算器"，这个理解能力来自Transformer对上下文的分析。

7为什么Transformer这么重要

Transformer的革命性在于三点：

  1. 并行计算：不再需要等待，可以同时处理所有字，速度提升几十倍
  2. 长期依赖：无论词相隔多远，都能直接建立联系，不再"健忘"
  3. 可扩展：模型越大，效果越好，这在此前的RNN时代是不可想象的

正是因为Transformer的出现，才有了GPT、BERT、T5等大模型，才有了今天的ChatGPT、Claude、Agent。

8写在最后

Transformer解决了"怎么让模型理解语言"的问题。但还有一个问题没有解决：

模型是怎么知道"小明喜欢小红"是对的，而不是"小红喜欢小明"？

这涉及到训练过程——模型是怎么从海量文本中学习语言规律的。这正是我们下一篇文章要讲的内容。
