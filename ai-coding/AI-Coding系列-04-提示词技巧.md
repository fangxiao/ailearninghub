## 为什么提示词很重要？

**同样的 Claude，不同的提示词，效果天壤之别：**

**差的提示词：**

```
写个函数
```

Claude 会问：什么函数？什么语言？什么功能？

<br/>

**好的提示词：**

```
用 Python 写一个函数：
- 功能：验证邮箱格式
- 参数：邮箱字符串
- 返回：布尔值
- 使用正则表达式
- 包含测试用例
```

Claude Code 会生成完整、高质量的代码。

<br/>

**结论：提示词质量 = 输出质量**

## 一、提示词的5个要素

### 1.1 完整的提示词结构

**黄金公式：**

```
背景 + 任务 + 要求 + 示例 + 格式
```

<br/>

**示例：**

```
【背景】我在做一个 Django 电商项目

【任务】写一个商品搜索 API

【要求】
- 支持关键词搜索
- 支持价格区间筛选
- 支持分页（每页20条）
- 返回 JSON 格式
- 包含错误处理

【示例】
请求：GET /api/products?keyword=iPhone&min_price=5000&max_price=10000&page=1
响应：{
  "products": [...],
  "total": 100,
  "page": 1,
  "pages": 5
}

【格式】
- 遵循 Django REST framework 规范
- 包含视图、序列化器、URL 配置
```

<br/>

### 1.2 要素详解

**1. 背景（Context）**

```
提供项目背景：
- 使用的框架/库
- 项目规模
- 技术栈
- 限制条件
```

<br/>

**2. 任务（Task）**

```
明确说明要做什么：
- 具体功能
- 输入输出
- 核心逻辑
```

<br/>

**3. 要求（Requirements）**

```
质量要求：
- 性能要求
- 安全要求
- 代码风格
- 文档要求
```

<br/>

**4. 示例（Examples）**

```
输入输出示例：
- 正常用例
- 边界用例
- 异常用例
```

<br/>

**5. 格式（Format）**

```
输出格式：
- 代码格式
- 文件结构
- 注释要求
```

## 二、常见错误和改进

### 2.1 错误1：太简单

**错误示例：**

```
写个登录功能
```

<br/>

**改进版本：**

```
用 Python Flask 实现用户登录功能：

1. 接收参数：用户名、密码
2. 验证：
   - 用户名长度 3-20
   - 密码至少8位
   - 数据库查询验证
3. 成功返回：
   - JWT token
   - 用户基本信息
4. 失败返回：
   - 错误信息
   - 状态码 401
5. 安全措施：
   - 密码加密存储
   - 防止 SQL 注入
   - 登录失败次数限制
```

<br/>

### 2.2 错误2：缺少上下文

**错误示例：**

```
优化这个函数：
[code]
```

<br/>

**改进版本：**

```
我在做一个数据处理项目，这个函数用于处理用户上传的 CSV 文件：

当前问题：
- 处理 10万行数据需要 30秒，太慢
- 内存占用过高（500MB+）

优化目标：
- 处理时间降到 5秒以内
- 内存占用控制在 100MB 以内

环境：
- Python 3.10
- Pandas 库
- 服务器 4核8G

[code]

请提供优化方案，并解释原理。
```

<br/>

### 2.3 错误3：矛盾要求

**错误示例：**

```
写一个快速排序：
- 时间复杂度 O(n)
- 稳定排序
```

**问题：** 快速排序平均 O(n log n)，不稳定

<br/>

**改进版本：**

```
实现一个高效的排序算法：

数据特点：
- 100万整数
- 范围 0-1000
- 有大量重复

要求：
- 时间复杂度尽可能低
- 稳定排序
- 内存占用合理

建议：考虑计数排序或基数排序
```

## 四、高级技巧

### 4.1 分步骤提问

**问题：** 一次性问太多，回答可能不深入

**技巧：** 分步提问，逐步深入

```
第1步：
"设计一个用户认证系统的架构"

第2步（基于第1步的回答）：
"根据这个架构，实现登录功能的代码"

第3步：
"为这个登录功能写单元测试"

第4步：
"优化这个测试的覆盖率"
```

<br/>

### 4.2 提供约束条件

**技巧：** 明确告诉 Claude 限制条件

```
实现一个缓存系统，要求：

约束条件：
- 不能使用第三方库
- 只用 Python 标准库
- Python 3.8+
- 单文件实现
- 代码不超过 200 行

功能：
- 支持 get/set/delete
- 支持 TTL（过期时间）
- 支持 LRU 淘汰
```

<br/>

### 4.3 要求解释

**技巧：** 要求 Claude 解释代码原理

```
用 Python 实现一个线程安全的单例模式

要求：
1. 完整代码
2. 解释实现原理
3. 说明为什么是线程安全的
4. 指出潜在问题
5. 提供测试方法
```

<br/>

### 4.4 对比方案

**技巧：** 要求提供多个方案对比

```
实现一个 Python Web API，有三种方案：
1. Flask
2. FastAPI
3. Django REST Framework

请对比这三种方案：
- 代码示例
- 性能对比
- 适用场景
- 优缺点

项目背景：
- 团队 3人
- API 数量约 50个
- 预计 QPS 1000
```

## 五、实战案例

### 案例1：学习新技术

**目标：** 学习 React Hooks

**提示词：**

```
我是 React 新手，想学习 Hooks。

请帮我：
1. 解释 useState 和 useEffect 的原理
2. 提供实用示例（计数器、数据获取）
3. 指出常见错误和避免方法
4. 推荐学习资源

要求：
- 代码简洁易懂
- 有详细注释
- 包含最佳实践
```

<br/>

### 案例2：优化性能

**目标：** 优化慢查询

**提示词：**

```
这个 SQL 查询很慢（10秒+），请帮我优化：

[SQL 语句]

表结构：
[表定义]

数据量：
- 表A：1000万行
- 表B：500万行

当前索引：
[索引信息]

优化目标：
- 查询时间降到 1秒以内
- 不改变表结构

请提供：
1. 问题分析
2. 优化方案（多个）
3. 索引建议
4. 优化后的 SQL
```

<br/>

### 案例3：代码重构

**目标：** 重构遗留代码

**提示词：**

```
我接手了一个遗留项目，需要重构这段代码：

目标：
1. 提升可读性
2. 降低耦合度
3. 增加可测试性
4. 性能不下降

约束：
- 不能改变对外接口
- 必须保持功能一致
- 循序渐进，可分步骤

当前问题：
- 函数太长（200行）
- 嵌套太深（5层）
- 缺少测试
- 难以维护

[粘贴代码]

请提供重构方案，包括：
1. 重构步骤
2. 每步的代码改动
3. 对应的测试
4. 注意事项
```
