二、什么是代码库理解？

代码库理解 = 让 AI 知道：

✅ 项目结构：有哪些目录和文件
✅ 技术栈：用了哪些框架和库
✅ 编码规范：代码风格和约定
✅ 业务逻辑：核心功能和模块关系
✅ 依赖关系：模块之间如何调用

效果对比：

没有理解 有理解
"修改这个函数" → 哪个文件？ "修改用户登录函数" → auth/login.py
"添加新功能" → 不知道在哪添加 "添加权限功能" → 扩展 middleware/
效率：⭐⭐ 效率：⭐⭐⭐⭐⭐

方法2：手动引导（推荐进阶）

核心思路： 像带新同事一样，逐步介绍项目

步骤1：介绍项目背景

用户：
这是一个 Flask 电商项目，主要功能包括：
- 用户管理（注册、登录、权限）
- 商品管理（CRUD、搜索、分类）
- 订单系统（购物车、支付、物流）
- 后台管理（数据统计、用户管理）

技术栈：
- Flask 2.3
- SQLAlchemy（ORM）
- Redis（缓存）
- Celery（异步任务）

步骤2：展示项目结构

用户：
项目结构如下：

app/
├── models/          # 数据模型
│   ├── user.py      # 用户模型
│   ├── product.py   # 商品模型
│   └── order.py     # 订单模型
├── views/           # 视图层
│   ├── auth.py      # 认证相关
│   ├── product.py   # 商品相关
│   └── order.py     # 订单相关
├── services/        # 业务逻辑
│   ├── auth_service.py
│   ├── product_service.py
│   └── order_service.py
└── utils/           # 工具函数
    ├── decorators.py
    └── validators.py

步骤3：说明编码规范

用户：
我们的编码规范：

1. 文件命名：snake_case（如 user_service.py）
2. 类命名：PascalCase（如 UserService）
3. 函数命名：snake_case（如 get_user_by_id）
4. 变量命名：snake_case（如 user_id）
5. 常量命名：UPPER_CASE（如 MAX_RETRY_COUNT）

6. 每个模块包含：
   - 类/函数定义
   - 类型注解
   - docstring
   - 单元测试（在 tests/ 目录）

步骤4：指出关键文件

用户：
关键文件：

1. app/__init__.py - Flask 应用初始化
2. config/config.py - 配置管理
3. app/models/base.py - 数据模型基类
4. app/utils/decorators.py - 通用装饰器（权限、缓存等）
5. app/services/ - 业务逻辑核心

依赖关系：
views → services → models
     ↘ utils

优点：

  • ✅ 深度理解项目
  • ✅ 可以强调重点
  • ✅ 符合团队习惯

缺点：

  • ⚠️ 需要时间准备
  • ⚠️ 需要对项目熟悉

3.3长期记忆

问题： 每次对话都要重新介绍项目

解决方案： 建立项目知识库

方法1：项目配置文件

yaml# .claude-code/project.yaml

project:
  name: "电商后台"
  type: "flask"
  
structure:
  models: "app/models/"
  views: "app/views/"
  services: "app/services/"
  
key_files:
  - "app/__init__.py"
  - "config/config.py"
  - "app/models/base.py"
  
conventions:
  naming: "snake_case"
  style: "pep8"
  
modules:
  auth:
    files:
      - "app/models/user.py"
      - "app/views/auth.py"
      - "app/services/auth_service.py"
