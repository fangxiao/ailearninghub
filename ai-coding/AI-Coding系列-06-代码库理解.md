## 二、什么是代码库理解？

**代码库理解 = 让 AI 知道：**

```
✅ 项目结构：有哪些目录和文件
✅ 技术栈：用了哪些框架和库
✅ 编码规范：代码风格和约定
✅ 业务逻辑：核心功能和模块关系
✅ 依赖关系：模块之间如何调用
```

**效果对比：**

| 没有理解 | 有理解 |
|----------|--------|
| "修改这个函数" → 哪个文件？ | "修改用户登录函数" → `auth/login.py` |
| "添加新功能" → 不知道在哪添加 | "添加权限功能" → 扩展 `middleware/` |
| 效率：⭐⭐ | 效率：⭐⭐⭐⭐⭐ |

## 二、建立项目上下文的 4 种方法

### 方法1：自动扫描（推荐新手）

**操作步骤：**

```bash
# 1. 进入项目目录
cd /path/to/your/project

# 2. 让 Claude Code 扫描项目
claude-code scan

# 3. 查看项目结构
claude-code tree
```

**Claude Code 会自动：**
- ✅ 识别项目类型（Python/JS/Go等）
- ✅ 分析目录结构
- ✅ 识别关键文件（README、package.json等）
- ✅ 生成项目概览

**示例输出：**

```
📁 项目分析结果

项目类型：Python Web Application
框架：Flask 2.3
规模：中型（127个文件，15,234行代码）

目录结构：
├── app/
│   ├── models/      # 数据模型（12个）
│   ├── views/       # 视图层（24个）
│   ├── services/    # 业务逻辑（18个）
│   └── utils/       # 工具函数（8个）
├── tests/           # 测试文件
├── config/          # 配置文件
└── requirements.txt # 依赖列表

核心模块：
- auth: 用户认证（5个文件）
- api: RESTful API（12个文件）
- db: 数据库操作（6个文件）
```

**优点：**
- ✅ 自动化，无需手动操作
- ✅ 快速建立项目上下文
- ✅ 适合新手

**缺点：**
- ⚠️ 可能漏掉业务逻辑细节
- ⚠️ 对复杂项目理解有限

<br/>

---

### 方法2：手动引导（推荐进阶）

**核心思路：** 像带新同事一样，逐步介绍项目

**步骤1：介绍项目背景**

```
用户：
这是一个 Flask 电商项目，主要功能包括：
- 用户管理（注册、登录、权限）
- 商品管理（CRUD、搜索、分类）
- 订单系统（购物车、支付、物流）
- 后台管理（数据统计、用户管理）

技术栈：
- Flask 2.3
- SQLAlchemy（ORM）
- Redis（缓存）
- Celery（异步任务）
```

**步骤2：展示项目结构**

```
用户：
项目结构如下：

app/
├── models/          # 数据模型
│   ├── user.py      # 用户模型
│   ├── product.py   # 商品模型
│   └── order.py     # 订单模型
├── views/           # 视图层
│   ├── auth.py      # 认证相关
│   ├── product.py   # 商品相关
│   └── order.py     # 订单相关
├── services/        # 业务逻辑
│   ├── auth_service.py
│   ├── product_service.py
│   └── order_service.py
└── utils/           # 工具函数
    ├── decorators.py
    └── validators.py
```

**步骤3：说明编码规范**

```
用户：
我们的编码规范：

1. 文件命名：snake_case（如 user_service.py）
2. 类命名：PascalCase（如 UserService）
3. 函数命名：snake_case（如 get_user_by_id）
4. 变量命名：snake_case（如 user_id）
5. 常量命名：UPPER_CASE（如 MAX_RETRY_COUNT）

6. 每个模块包含：
   - 类/函数定义
   - 类型注解
   - docstring
   - 单元测试（在 tests/ 目录）
```

**步骤4：指出关键文件**

```
用户：
关键文件：

1. app/__init__.py - Flask 应用初始化
2. config/config.py - 配置管理
3. app/models/base.py - 数据模型基类
4. app/utils/decorators.py - 通用装饰器（权限、缓存等）
5. app/services/ - 业务逻辑核心

依赖关系：
views → services → models
     ↘ utils
```

**优点：**
- ✅ 深度理解项目
- ✅ 可以强调重点
- ✅ 符合团队习惯

**缺点：**
- ⚠️ 需要时间准备
- ⚠️ 需要对项目熟悉

### 方法3：README 驱动（推荐团队）

**核心思路：** 写一份详细的 README，让 AI 自动理解

**README 模板：**

```markdown
# 项目名称

## 项目简介
这是一个 Flask 电商项目，提供用户管理、商品管理、订单系统等功能。

## 技术栈
- Flask 2.3
- SQLAlchemy（ORM）
- Redis（缓存）
- Celery（异步任务）

## 项目结构

app/
├── models/      # 数据模型
├── views/       # 视图层
├── services/    # 业务逻辑
└── utils/       # 工具函数

## 核心模块

### 用户模块（app/models/user.py, app/views/auth.py）
- 用户注册、登录、权限管理
- 依赖：app/services/auth_service.py

### 商品模块（app/models/product.py, app/views/product.py）
- 商品 CRUD、搜索、分类
- 依赖：app/services/product_service.py

### 订单模块（app/models/order.py, app/views/order.py）
- 购物车、订单创建、支付
- 依赖：app/services/order_service.py

## 编码规范

- 文件命名：snake_case
- 类命名：PascalCase
- 函数命名：snake_case
- 必须添加类型注解和 docstring

## 开发指南

1. 新增功能：在 app/views/ 添加视图，app/services/ 添加业务逻辑
2. 数据模型：在 app/models/ 添加，继承 app/models/base.py
3. 测试：在 tests/ 目录添加单元测试

## 常见任务

- 添加新 API：参考 app/views/product.py
- 添加新模型：参考 app/models/product.py
- 添加新服务：参考 app/services/product_service.py
```

**使用方法：**

```bash
# Claude Code 会自动读取 README
cd /path/to/project
claude-code chat

# 直接开始对话，AI 已经理解项目
你：帮我添加一个评论功能
AI：好的，我会参考商品模块的结构，在 app/models/ 添加 comment.py，
    在 app/views/ 添加 comment.py，在 app/services/ 添加 comment_service.py
```

**优点：**
- ✅ 一次编写，长期受益
- ✅ 团队成员都能用
- ✅ 方便项目交接

**缺点：**
- ⚠️ 需要维护 README
- ⚠️ 初次编写需要时间

## 三、上下文管理技巧

### 3.1 Token 管理

**问题：** 项目太大，超过 200K tokens 限制

**解决方案：** 优先级管理

```
优先级1（必须包含）：
✅ 项目结构概览
✅ 核心模块代码
✅ 关键配置文件
✅ README 文档

优先级2（重要包含）：
⭐ 常用工具函数
⭐ 数据模型定义
⭐ 接口定义

优先级3（按需包含）：
⚠️ 测试代码
⚠️ 文档注释
⚠️ 示例代码

优先级4（可以省略）：
❌ 第三方库代码
❌ 生成的代码
❌ 历史代码
```

**实际操作：**

```python
# 方法1：指定关键文件
你：重点关注这些文件：
    - app/services/order_service.py
    - app/models/order.py
    - app/views/order.py
    
# 方法2：排除次要文件
你：忽略这些文件：
    - tests/
    - docs/
    - migrations/

# 方法3：使用摘要
你：这个文件只看前50行就行，后面都是CRUD
```

### 3.3 长期记忆

**问题：** 每次对话都要重新介绍项目

**解决方案：** 建立项目知识库

**方法1：项目配置文件**

```yaml
# .claude-code/project.yaml

project:
  name: "电商后台"
  type: "flask"
  
structure:
  models: "app/models/"
  views: "app/views/"
  services: "app/services/"
  
key_files:
  - "app/__init__.py"
  - "config/config.py"
  - "app/models/base.py"
  
conventions:
  naming: "snake_case"
  style: "pep8"
  
modules:
  auth:
    files:
      - "app/models/user.py"
      - "app/views/auth.py"
      - "app/services/auth_service.py"
```

**方法2：对话历史保存**

```bash

# 下次加载

```

```
    - 用户认证
    - 数据库模型

AI：好的，我会重点理解这些核心模块。
```

**步骤2：按需深入**

```
你：现在我要修改订单模块，请理解这部分代码。
    文件：app/services/order_service.py

AI：好的，我会深入分析这个文件及其依赖。
```

**步骤3：保持上下文**

```
你：记住，这个项目使用了：
    - Redis 缓存
    - Celery 异步任务
    - 分层架构（views → services → models）

AI：好的，我记住了这些关键信息。
```

<br/>

### 4.2 微服务项目怎么办？

**场景：** 项目是微服务架构，多个服务

**解决方案：** 服务级别理解

```
项目结构：

services/
├── user-service/      # 用户服务
├── product-service/   # 商品服务
└── order-service/     # 订单服务

# 方法1：单独理解每个服务
你：先理解 user-service

# 方法2：理解服务间通信
你：这些服务如何通信？
AI：通过 REST API 和消息队列

# 方法3：理解当前工作的服务
你：我现在在改 order-service，请理解这个服务
```

<br/>

### 4.3 遗留代码怎么办？

**场景：** 项目是老代码，没有文档

**解决方案：** 反向理解

```

    - 目录：app/, lib/, config/
    - 主要文件：app.py, models.py

# 步骤2：识别关键模块
你：找出最重要的 10 个文件

AI：根据代码量和依赖关系，重要文件是：
    1. app.py（主程序）
    2. models.py（数据模型）
    3. routes.py（路由定义）
    ...

# 步骤3：生成文档
你：为这个项目生成 README

AI：好的，我已经生成了项目 README...
```
