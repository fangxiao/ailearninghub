## 二、功能设计：MVP vs 完整版

### 2.1 什么是MVP？

**MVP = Minimum Viable Product（最小可行产品）**

```
MVP原则：
• 只做最核心的功能
• 快速上线验证
• 根据反馈迭代
• 避免过度设计
```

<br/>

### 2.2 小王助手的功能规划

**MVP版本（第1周）：**

```
核心功能：
✅ 日程提醒
   - 连接飞书日历
   - 每天早上8点推送今日日程
   - 会议前15分钟提醒

✅ 简单待办
   - 添加待办事项
   - 标记完成
   - 每日回顾

✅ 基础交互
   - 飞书私聊
   - 自然语言理解
```

**完整版（第2周及以后）：**

```
扩展功能：
• 会议纪要（语音转文字）
• 邮件摘要（连接邮箱）
• 智能建议（根据习惯推荐）
• 项目追踪（进度管理）
• 周报生成（自动汇总）
```

<br/>

### 2.3 功能优先级矩阵

```
           高价值
              ↑
    ┌─────────┼─────────┐
    │  优先做  │  也要做  │
    │ (MVP)   │ (V2.0)  │
────┼─────────┼─────────┼───→ 高频
    │  可选做  │  暂不做  │
    │ (V3.0)  │ (砍掉)  │
    └─────────┼─────────┘
              ↓
           低价值
```

**小王的功能优先级：**

| 功能 | 价值 | 频率 | 优先级 |
|------|------|------|--------|
| 日程提醒 | 高 | 每天 | P0（MVP） |
| 待办管理 | 高 | 每天 | P0（MVP） |
| 会议纪要 | 高 | 每周2-3次 | P1（V1.5） |
| 邮件摘要 | 中 | 每天 | P2（V2.0） |
| 项目追踪 | 中 | 每周 | P2（V2.0） |
| 周报生成 | 低 | 每周 | P3（V3.0） |

## 四、架构设计：单Agent vs 多Agent

### 4.1 架构选项

**选项A：单Agent（推荐新手）**

```
┌─────────────────────────────┐
│         主Agent             │
│  ┌─────────────────────┐   │
│  │  意图识别            │   │
│  │  日程/待办/提醒      │   │
│  │  对话管理            │   │
│  └─────────────────────┘   │
└─────────────────────────────┘

优点：
✅ 简单易懂
✅ 调试方便
✅ 资源占用少

缺点：
❌ 功能耦合
❌ 扩展性一般
```

<br/>

**选项B：多Agent（进阶）**

```
┌──────────┐    ┌──────────┐    ┌──────────┐
│ 调度Agent │───→│ 日程Agent │    │ 待办Agent │
└──────────┘    └──────────┘    └──────────┘
     ↓
┌──────────┐
│ 提醒Agent │
└──────────┘

优点：
✅ 模块化
✅ 易扩展
✅ 可并行

缺点：
❌ 复杂度高
❌ 通信成本
```

<br/>

**选项C：工作流模式（推荐）**

```
┌─────────────────────────────────────┐
│            主工作流                  │
│  ┌─────┐   ┌─────┐   ┌─────┐      │
│  │意图  │→ │路由  │→ │执行  │      │
│  │识别  │   │分发  │   │任务  │      │
│  └─────┘   └─────┘   └─────┘      │
└─────────────────────────────────────┘

优点：
✅ 清晰的流程
✅ 易于调试
✅ 平衡复杂度
```

<br/>

### 4.2 小王的架构选择

**选择：工作流模式**

```yaml
# 架构设计
architecture:
  模式: 工作流
  
  组件:
    - 入口: 飞书消息接收
    - 意图识别: LLM分类
    - 路由分发: 根据意图分发
    - 任务执行: 对应Skill
    - 结果返回: 飞书消息
  
  数据流:
    用户消息 → 意图识别 → 路由 → Skill执行 → 返回结果
```

## 五、数据模型设计

### 5.1 待办事项

```python
# models/todo.py
from dataclasses import dataclass
from datetime import datetime
from typing import Optional

@dataclass
class Todo:
    """待办事项"""
    id: str                    # 唯一ID
    title: str                 # 标题
    description: str           # 描述
    status: str                # pending/completed
    priority: str              # high/medium/low
    due_date: Optional[datetime]  # 截止时间
    created_at: datetime       # 创建时间
    completed_at: Optional[datetime]  # 完成时间
    tags: list[str]            # 标签

# 存储结构（SQLite）
"""
CREATE TABLE todos (
    id TEXT PRIMARY KEY,
    title TEXT NOT NULL,
    description TEXT,
    status TEXT DEFAULT 'pending',
    priority TEXT DEFAULT 'medium',
    due_date TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    completed_at TIMESTAMP,
    tags TEXT  -- JSON格式
);
"""
```
