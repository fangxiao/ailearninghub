让 AI 在写代码前先拷问你 50 个问题——grill-me 实战

Matt Pocock 的爆款 Skill，812k 安装量的需求对齐利器

AI 编程规划 Skill 推荐 | Claude Code 需求澄清实战

用 AI 写代码，最经典的翻车现场是这个：

❌ 你说"帮我加个登录"，AI 不问"要不要记住设备""失败几次锁账号""session 多久过期"，直接铺一套它觉得合理的方案

❌ 你 review 时 AI 已经写了 500 行，回炉重写两小时

❌ 你以为脑子里的需求很清楚，AI 一写出来，完全不是那回事

❌ 反复改 prompt、反复生成、反复推翻，Token 烧了一堆还是没对齐

Matt Pocock（TypeScript 圈的大佬）在自己的演讲里讲过这段体感："我运行它，我尽量不看代码，但我还是看了，然后我发现代码更糟了。我又来了一次，更糟……最后就是一堆垃圾。" 他把这个失败模式叫 "Agent 没做我想要的"——代码写得不算慢，问题在于需求还没对齐，AI 就已经把代码写完了。

他的解法是一个不到 15 行的 Skill：grill-me。在 AI 动手写代码之前，先反过来拷问你，一个一个地问，每个问题都给推荐答案，直到你们对要做什么达成共识。这个 Skill 在 skills.sh 上累计 812k 安装量，是 Matt 仓库里最火的一个。

它在干什么：让 Claude Code 在写代码前，沿着设计树逐个拷问你的需求，每个问题带推荐答案，直到模糊需求全部落地。812k 安装，Matt Pocock 出品。

01 为什么需要 grill-me？design concept 跑偏

Matt 引用《程序员修炼之道》里的一句话："没有人确切知道自己想要什么。" 这不是讽刺，是事实，你脑子里的需求是模糊的，你以为它清楚，但一旦落地就发现到处是洞。

更深的解释来自 Frederick P. Brooks（《人月神话》作者）在《The Design of Design》里提的 design concept（设计概念）：当多人合作设计一个东西时，你们之间会有一个正在被造出来的东西——它在脑子里飘着，是个隐形的"关于这个东西的理论"。AI 一上来就动手写代码，等于它压根没和你共享同一个 design concept。最后写出来的东西，毛病往往不是语法，而是前提。

Brooks 给的工具叫 design tree（设计树），把一个决策拆成多分支，每个分支再拆。你不能跳过上游决策直接做下游决策，否则上游一变下游全要重做。比如你说"做登录"，上游是"鉴权方式"（账号密码 / SSO / OAuth），选了 SSO，下游的"密码策略"问题就自动消失了，不用问。

grill-me 做的就是这件事：在写代码前，沿着 design tree 从根到叶逐个拷问，把模糊需求逼清楚。它跟 Superpowers 工程化流程里的"Brainstorming 头脑风暴"阶段是同一个思路，先想清楚再动手（参见《Superpowers 把 AI 编程从凭感觉变按流程》），也跟 pm-skills 写 PRD 前的需求澄清对齐（参见《pm-skills 产品经理技能市场》）。

02 15 行 SKILL.md：每一句都是设计

grill-me 的 SKILL.md 全文加 frontmatter 不到 15 行，但每一句都在压住 LLM 的某个坏习惯：

---

name: grill-me

description: Interview the user relentlessly about a plan or design

---

Interview me relentlessly about every aspect of this plan until we reach a shared understanding. Walk down each branch of the design tree, resolving dependencies between decisions one-by-one. For each question, provide your recommended answer.

Ask the questions one at a time.

If a question can be answered by exploring the codebase, explore the codebase instead.

逐句拆解，每一句都在解决一个具体的 LLM 失败模式：

"interview me relentlessly" — 关键词是 relentlessly（不放过）。LLM 默认问 1-2 个问题就觉得"差不多了"开始动手。这个词强行压住这个倾向。

"walk down each branch of the design tree" — Brooks 的 design tree。强迫 Claude 把需求当树，先解上游再解下游。

"resolving dependencies one-by-one" — 禁止打包提问。决策之间有依赖，先确定上游能砍掉一堆下游问题。

"provide your recommended answer" — AI 不只问，还给推荐答案。你只需点头/否决，省 80% 输入时间。

"one at a time" — 防止一次甩 10 个问题让你头大。

"explore the codebase instead" — 能查代码就别问用户。AI 能自己看的（比如"项目用的什么框架"）就自己看，只把真正的决策留给你。

这就是 prompt as software——15 行指令，每一行都在堵一个已知的失败模式。跟 anthropics/skills 官方 Skill 库强调的"指令要小而精、可组合"是同一个设计哲学（参见《anthropics/skills 官方技能库》）。

03 安装：30 秒两种方式

Matt 的仓库（mattpocock/skills）在 Claude Code 官方市场里，提供两种安装哲学：插件式（托管、自动更新）和文件式（可编辑、自己拥有）。

方式一：Claude Code 插件（推荐，自动更新）

# 命令行安装

claude plugins install mattpocock-skills

# 或在 Claude Code 会话内

/plugin install mattpocock-skills

官方市场直装，不用先 add marketplace。Matt 发新版会自动更新，你订阅的是一份只读副本。

方式二：skills.sh 文件式（可编辑，支持 Codex 等）

# 交互式选择要装哪些 skill

npx skills@latest add mattpocock/skills

把 skill 文件写进你的仓库，你拥有它们、可以改。想拉新版跑 npx skills update。两种方式选一种就行，都装会重复。

方式三：直接告诉 Agent

帮我安装 github.com/mattpocock/skills 中的 grill-me skill

04 实战：一次完整的拷问

假设你要给项目加一个登录功能。不装 grill-me，你会直接说"加个登录"，AI 闷头写 500 行。装了 grill-me，流程变成这样：

触发拷问

# 方式一：斜杠命令

/grill-me

# 方式二：自然语言

grill me on this plan: 给项目加登录功能

拷问过程（模拟）

AI Q1：鉴权方式用哪种？推荐：账号密码 + JWT，因为项目已有用户表

你：用 OAuth，接 GitHub 和 Google

AI Q2：那密码策略问题跳过。OAuth 回调地址用哪个域名？推荐：localhost:3000/auth/callback 开发期，生产配 yourapp.com

你：同意推荐

AI Q3：Session 过期时间？推荐：7 天，refresh token 30 天

你：session 1 天，refresh 7 天，安全优先

AI Q4：失败登录要锁定吗？推荐：5 次失败锁 15 分钟，但你用了 OAuth，这条只对绑定本地账号的场景生效

你：暂不绑本地账号，跳过

注意几个细节：Q1 选了 OAuth 后，Q4 自动标注"这条对你不太生效"，这就是 design tree 在工作，上游决策砍掉了下游问题。每个问题都带推荐答案，你只需说"同意"或改。整个流程通常 30-45 分钟，但省下的是后面回炉重写的两小时。

拷问结束后，AI 会和你确认"shared understanding"（共识），确认后才动手写代码。这跟 Planning with Files 把计划写进 task_plan.md 持久化是互补的，grill-me 负责把需求逼清楚，Planning with Files 负责把逼清楚的计划存下来防 AI 健忘（参见《Planning with Files AI 健忘症解决方案》）。

05 衍生版本：从拷问到自动驾驶

grill-me 太火了，社区在它基础上长出了几个衍生版本，把"拷问"扩展成了完整的自动化链路。

版本 在 grill-me 上加了什么 仓库
drill-me 拷问 + 自动模式，AI 自己走完决策树 lukeselr/claude-autonomy-kit
autopilot-loop 拷问 → 构建 → 测试 → 提交，自动循环 lukeselr/claude-autonomy-kit
grill-with-docs 拷问时对照项目 CONTEXT.md 术语表 + 写 ADR mattpocock/skills（官方）
grill-me-codex Claude 拷问 + Codex 对抗审查 + Codex 构建 chaseai-yt/grill-me-codex

最值得说的是 Claude Autonomy Kit（lukeselr 出品），它把 grill-me 扩展成四件套。灵感来自 Boris Cherny（Claude Code 的创造者）的一句话："我不再 prompt Claude 了。我让循环跑着。我的工作是写循环。" 这套 kit 就是教你写循环的：grill-me 对齐需求 → drill-me 自动解决策 → autopilot-loop 自动构建测试提交。

安装 Claude Autonomy Kit

# 克隆仓库后复制 skill

cp -R skills/* ~/.claude/skills/

grill-me-codex（chaseai-yt 出品）走得更远：Act 1 用 Claude 拷问你锁定计划，Act 2 把计划交给 OpenAI Codex 做对抗性审查（换个模型挑刺，因为同一个模型不能给自己改卷），Act 3 角色翻转，Codex 写代码，Claude review diff。双模型交叉验证，是 grill-me 在多模型协作上的延伸。

06 避坑指南：4 个常见问题

⚠️ 坑 1：拷问太久，30 分钟还没开始写
grill-me 是 user-invoked skill（只能你手动触发，AI 不会自作主张启动）。对于 trivial 任务（改个文案、调个样式）不需要拷问，直接说就行。Matt 自己说："Skip it for trivial or fully-specified tasks。" 它是为 non-trivial 设计的。

⚠️ 坑 2：AI 不按 design tree 走，跳着问
这通常是模型能力不够。grill-me 依赖模型理解"design tree"和"dependency"概念，推荐用 Claude Sonnet 4 以上。如果跳着问，可以在回答后补一句"先解决上游决策再问下游"。

⚠️ 坑 3：推荐答案总是"默认选项"，不够 sharp
推荐答案的质量取决于 AI 对你项目的理解。首次用之前，先让 AI 读一遍代码库（"explore the codebase"那条指令就会触发）。也可以配合 grill-with-docs 版本，它会读你的 CONTEXT.md 术语表，推荐更贴合项目。

⚠️ 坑 4：两种安装方式都装了，skill 出现两份
Matt 在 README 里明确警告："installing both leaves you with every skill twice。" 插件式和文件式选一种。如果误装了双份，删掉 ~/.claude/skills/ 里手动复制的那些，保留插件版即可。

07 横向对比：grill-me vs Plan Mode vs Superpowers

工具 核心理念 触发方式 推荐答案
grill-me 先拷问再动手，消解模糊需求 /grill-me 手动触发 ✅ 每问必给
Claude Plan Mode 先生成计划再执行 自动 / Shift+Tab ❌ 不问只列
Superpowers 5 步工程化流程 流程内置 brainstorming 部分场景给
Planning with Files 计划持久化防健忘 自动写 task_plan.md ❌ 不问只存

简单说：Plan Mode 是"AI 列计划给你看"，单向输出；grill-me 是"AI 问你问题"，双向对齐。Plan Mode 更像"先给你看菜单"，grill-me 更像"先把你脑子里的模糊需求逼清楚"。两者不冲突，可以先 grill-me 对齐，再让 Plan Mode 出执行计划。

跟 Superpowers 的关系是包含式的：Superpowers 的第一步 Brainstorming 本质就是一次 grill，你可以把 grill-me 装进去当 Brainstorming 阶段的执行器。跟 TDD-skills 的"先写测试再写代码"也是同一个哲学的不同阶段，grill-me 管的是"写代码前"，TDD 管的是"写代码时"（参见《TDD-skills 强制 AI 先写测试》）。
