让 AI 写完代码自动扫漏洞——Snyk Security Skills 实战

Secure at Inception，AI 代码安全从源头管起

AI 安全工具推荐 | Claude Code 漏洞修复 Skill

用 AI 写代码快是真快，但安全这件事越来越让人头大：

❌ AI 一晚上生成几千行代码，SQL 注入、硬编码密钥、依赖漏洞全埋在里面

❌ 代码已经合进主分支，安全扫描在 CI 里跑完才发现漏洞，修复成本翻倍

❌ npm install 一个新包，AI 不管有没有 CVE 直接用，依赖雪球越滚越大

❌ SAST 扫描报告几百条，人工分类 + 改代码 + 写 PR，一个漏洞耗半天

这些问题的根子是：安全检查跑在 AI 写代码之后。传统 SAST/SCA 工具都在 PR 或 CI 阶段才介入，等扫描报告出来，代码已经写完、测过、合进了。Snyk Studio Recipes 提出的解法叫 Secure at Inception：把扫描塞进 AI 写代码的循环里，漏洞在生成的瞬间就被拦下来。

一句话总结：Snyk 官方开源的 AI 编程安全 Recipes，一个命令装好，支持 Claude Code / Cursor / Copilot 等 6 个助手，自动扫描 + 自动修复 + 自动建 PR。

01 什么是 Secure at Inception？

AI 编程助手以机器速度生成代码，传统安全工具在 PR、CI、部署阶段才扫描，那时候代码已经定型，漏洞已经影响了设计、测试和开发者的判断，再回头改成本极高。

Secure at Inception 把这个流程翻转：扫描在代码生成的那一刻就跑，直接嵌在助手的循环里。AI 写完一段代码，Snyk 立刻扫，发现漏洞当场修，根本不让它进 commit。这是 Snyk 对"AI 时代安全怎么做"的回答，也是 studio-recipes 这个仓库的主要思路。

跟之前介绍过的 ECC 自带的 /security-scan 和 wshobson/agents 里的 security-audit agent 不同，那些是通用扫描器，而 Snyk Studio Recipes 是把 Snyk 平台的 SAST + SCA 能力直接接进 AI 助手，扫描精度、漏洞库覆盖、修复建议都是企业级的。

02 四大 Recipe 类型：从拦截到修复

studio-recipes 不是单一 Skill，而是按"什么时候触发"分成的四类 Recipe：

Recipe 类型 作用 触发时机
Secure at Inception 护栏 AI 写代码时实时扫描漏洞 助手写代码的每一刻
Secure at Commit 护栏 拦截带漏洞的 git commit git commit 时
包强制护栏 拦截有风险的依赖安装 添加依赖时
修复命令与 Skill /snyk-fix 一键修漏洞 开发者主动调用

前三类是自动护栏，装上就一直在跑，开发者无感；第四类是按需修复，遇到历史漏洞债时主动喊 /snyk-fix，AI 走一遍"扫描 → 分析 → 修复 → 验证 → 建 PR"的完整流程。

所有 Recipe 都通过 Snyk MCP Server 接入底层能力：SAST 走 Snyk Code 扫代码漏洞（SQL 注入、XSS、硬编码密钥），SCA 走 Snyk Open Source 扫依赖漏洞（npm/pip/maven 包的 CVE）。两层覆盖，AI 写出来的代码和引的包都被管住。

03 安装：一条命令搞定六大助手

studio-recipes 最大的设计亮点是一个自解压安装器覆盖所有助手。它会自动检测你装了哪些 AI 编程工具（Claude Code、Cursor、Copilot、Gemini、Windsurf、Kiro），把对应的 Recipe 合并进去。前置要求只有一条：有 Snyk 账号（免费版也行）。

① 安装 Recipe（macOS / Linux）

# 下载安装脚本

curl -fsSL 'https://raw.githubusercontent.com/snyk/studio-recipes/main/installer/dist/snyk-studio-install.sh' -o snyk-studio-install.sh

# 执行安装

bash ./snyk-studio-install.sh

① 安装 Recipe（Windows）

powershell -ExecutionPolicy Bypass -File .\snyk-studio-install.ps1

安装器会自动引导 bootstrap uv（Python）、Node.js、npm、Snyk CLI，每步都会先问过你再装。想先看会装什么，加 --dry-run 预览；只想装某一个助手，加 --ade claude-code 指定。

② 认证 Snyk

# 交互式登录

snyk auth

# 或者非交互式（CI / 容器）

export SNYK_TOKEN=your_token_from_app.snyk.io/account

装完打开 Claude Code，让它写一段碰数据库或网络的代码，你应该能立刻看到 Snyk 自动跑起来。然后试试 /snyk-fix 在已有项目上跑修复流程。

04 /snyk-fix 实战：七步修一个漏洞

主动调用 /snyk-fix 或直接说"fix security issues"，AI 会按下面这七步走完整修复流程：

① 解析请求 — 理解你想修什么（自动判断 SAST 还是 SCA，默认先修优先级最高的）

② Snyk 扫描 — 调 Snyk Code 扫代码漏洞，或 Snyk Open Source 扫依赖 CVE

③ 分析结果 — 按严重程度（Critical / High / Medium / Low）排序，挑出最该修的

④ 修复漏洞 — AI 改代码或升依赖版本

⑤ 验证修复 — 重新跑一遍 Snyk 扫描，确认漏洞真没了（这步呼应 TDD-skills 的 RED-GREEN-REFACTOR 循环，验证是流程的硬性一环，参见《TDD-skills 强制 AI 先写测试》）

⑥ 汇总报告 — 列出修了什么、改了哪些文件、剩余风险

⑦ 建 PR — 可选步骤，自动创建 Pull Request 把修复提交进代码库

常用调用方式

# 自动判断扫描类型，修最高优先级漏洞

/snyk-fix

# 批量修所有 Critical 和 High

/snyk-batch-fix --severity critical,high

# 自然语言触发

fix security issues in src/auth/

第 ⑤ 步的"验证修复"是关键。这跟 Superpowers 工程化流程里"先写测试 → 跑测试 → 验证通过才能进下一步"是同一个思路（参见《Superpowers 把 AI 编程从凭感觉变按流程》），也跟 anthropics/skills 官方 Skill 强调的"输出可验证"对齐（参见《anthropics/skills 官方技能库》）。Secure at Inception 是闭环：扫完就验。

05 进阶：Snyk Security Expert Agent

studio-recipes 是 Snyk 官方作品，开箱即用。如果想要更深度的威胁建模和企业级评估，社区还有个 claude-snyk-security-expert（markusweldon 维护），它把 Snyk 能力包装成一个独立 subagent，主打 25+ 年安全专家视角的应用安全审查。

前置依赖

# 装 Snyk CLI

npm install -g snyk

# 认证

snyk auth

装 subagent

# 拉仓库

git clone https://github.com/markusweldon/claude-snyk-security-expert.git

# 装到用户级（所有项目可用）

mkdir -p ~/.claude/agents

cp claude-snyk-security-expert/.claude/agents/snyk-security-expert.md ~/.claude/agents/

挂 Snyk MCP Server

# 启动 Snyk MCP（STDIO 模式）

snyk mcp -t stdio --experimental

# 在 Claude Code 里挂载

claude mcp add snyk -- snyk mcp -t stdio --experimental

装完后，在 Claude Code 里说"用 snyk-security-expert 做一次应用安全审查"，subagent 会以安全专家视角通读你的代码，输出威胁建模报告 + 修复建议 + 优先级排序。这跟 wshobson/agents 的 security-audit 是同类型工具，但 Snyk 版本因为接了真实漏洞库，扫描结果更准（参见《wshobson/agents 生产级 subagent 集合》）。

06 避坑指南：4 个常见问题

⚠️ 坑 1：扫不出来任何漏洞
99% 是没认证。装完一定要跑 snyk auth，或设 SNYK_TOKEN。免费账号每周有扫描次数限制，团队规模大需要 Team 或 Enterprise 版。

⚠️ 坑 2：MCP Server 启动失败
snyk mcp 还是 experimental 阶段，要求 Snyk CLI ≥ 1.1294.0。先 npm update -g snyk 升到最新。Windows 下 STDIO 模式偶尔有编码问题，建议用 SSE 模式替代。

⚠️ 坑 3：/snyk-fix 改完代码测试挂了
Snyk 的修复偏保守，升依赖版本可能引入 Breaking Change。建议修复前先确认项目有测试覆盖（没有的话先用 TDD-skills 补测试），修复后立刻跑回归。Superpowers 流程里"验证"那一步就是干这个的。

⚠️ 坑 4：Secure at Commit 拦不住
这类 Recipe 是 experimental 状态，依赖 git hook 注入。如果用 --no-verify 提交会绕过，团队协作时要约束不能用这个 flag。Husky 用户需要把 Snyk 的 pre-commit hook 手动挂进 husky 配置。

07 横向对比：和同类安全工具差在哪

工具 扫描能力 自动修复 实时拦截
Snyk Studio Recipes SAST + SCA，企业级漏洞库 /snyk-fix 全自动 + 建 PR ✅ 写代码时实时
ECC /security-scan 规则匹配，覆盖 OWASP Top 10 只给建议，不自动改 按需触发
wshobson security-audit 通用安全审查，无漏洞库 输出报告，不自动改 按需触发
GitHub Dependabot 仅 SCA（依赖 CVE） 升版本 PR PR 阶段才介入

简单总结：Dependabot 只管依赖、且只在 PR 阶段；ECC 和 wshobson 是通用扫描、给建议不修代码；Snyk Studio Recipes 是唯一做到"写代码时实时扫 + 自动改 + 自动建 PR"的完整方案，而且 SAST + SCA 双覆盖。预算够的话，Snyk 配合 ECC 的 /security-scan 一起用，企业级项目安全基本能闭环。

顺带一提：装完 Snyk 后，AI 输出的安全报告默认是英文长段落，i-have-adhd Skill 能把它转成"答案先行 + 分步骤"的格式，扫一眼就能抓重点（参见《i-have-adhd 让 AI 输出对 ADHD 友好》）。安全报告可读性和安全本身一样重要。

Secure at Inception：
安全从代码写出的那一刻就管住，比事后返工省心得多。
