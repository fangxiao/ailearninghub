❌ 测试验证无人盯：写完不知道对不对，要自己写客户端连上去一个一个试

❌ 重复造轮子：每个 Server 都得把上面这套流程再来一遍，10 个 Server 写 10 次

一句话总结：Anthropic 官方 4 阶段工作流 Skill，支持 TypeScript 和 Python 双语言，自动激活，一句话生成完整可用的 MCP Server。

01 MCP Builder 是什么？

MCP Builder 是 Anthropic 官方维护的一个 Skill，本质是一份加载到 Claude Code 中的工作流定义文件。装上之后，它会按照固定的 4 阶段流程帮你搭建 MCP Server，无需手动处理协议细节。

🎯 官方维护：Anthropic 出品，与 MCP 协议规范同步更新

⚙️ 4 阶段工作流：Research → Implement → Test → Evaluate，全自动串起来

🌐 双语言支持：TypeScript 和 Python 任选，按你的技术栈来

⚡ 自动激活：检测到"搭 MCP Server"相关需求时自动启动，不用记命令

📊 自带评估：内置评估工具，给生成的 Server 打分，质量看得见

简单说，它把"搭 MCP Server"这件事从手工活变成了流水线作业。你只管提需求，研究、实现、测试、评估都交给它。

02 两种安装方式，挑一个就行

MCP Builder 提供两种安装方式，推荐第一种插件市场方式，省心省事。

1 推荐：插件市场安装（两条命令搞定）

在 Claude Code 对话框依次输入下面两行命令：

/plugin marketplace add make-heavy-metal/mcp-builder # 添加插件市场

/plugin install mcp-builder@make-heavy-metal # 安装插件

装完即用，下次说"帮我搭一个 MCP Server"就会自动激活工作流。

2 本地开发：git clone（适合想改源码的同学）

把仓库 clone 下来，放到 Claude Code 的 skills 目录：

git clone https://github.com/make-heavy-metal/mcp-builder.git # 克隆仓库到本地

评估工具需要装一下 Python 依赖：

pip install -r scripts/requirements.txt # 安装评估工具依赖

💡 选哪个？99% 的同学选第一种就够。第二种适合想给 MCP Builder 提 PR、改工作流的开发者。

03 4 阶段工作流详解：Research → Implement → Test → Evaluate

MCP Builder 的核心是它的 4 阶段工作流。下面每个阶段用不同颜色卡片区分，方便对照理解：

① Research 研究阶段

目标：搞清楚你要对接的服务有什么 API、能力边界在哪、有没有现成的 SDK。

动作：读官方文档、查 API Reference、扫描现有 SDK、列出可作为 MCP 工具暴露的能力清单。输出一份"研究简报"作为下一阶段的输入。

② Implement 实现阶段

目标：根据研究简报生成完整 MCP Server 代码。

动作：按你选的语言（TypeScript 或 Python）生成项目骨架，注册工具、定义 schema、实现具体逻辑、处理错误。代码风格遵循官方 MCP SDK 推荐。

③ Test 测试阶段

目标：验证 Server 能跑、工具能用、错误处理正常。

动作：启动 Server 进程、模拟客户端连接、逐个调用工具检查返回值、构造异常输入验证错误处理。发现的问题自动回到 Implement 阶段修复。

④ Evaluate 评估阶段

目标：给生成的 Server 打分，量化质量。

动作：调用 /mcp-builder:evaluate 跑评估脚本，从协议合规、工具完整性、错误处理、文档完备性等维度打分，输出报告。

四个阶段串起来：Research 喂给 Implement，Implement 输出给 Test，Test 发现问题回 Implement，全部通过后 Evaluate 打分。整个过程不需要你切换上下文，工作流自动衔接。

04 实战演示：搭一个 Notion MCP Server

说再多不如看一遍完整流程。需求很简单："给 Claude 装上读写 Notion 的能力"。下面是 MCP Builder 自动跑完 4 阶段的对话实录：

1 用户提需求

"帮我搭一个 Notion 的 MCP Server，要支持查询数据库、读取页面、创建页面三个工具，用 TypeScript。"

MCP Builder 检测到关键词，自动激活 4 阶段工作流。

2 Research：自动研究 Notion API

MCP Builder 自动完成：

  • 访问 Notion API 官方文档，确认 v1 接口路径
  • 识别三个目标能力：query database / retrieve page / create page
  • 检查到官方有 @notionhq/notion-client SDK 可复用
  • 列出鉴权方式：Bearer Token，从环境变量 NOTION_API_KEY 读取
  • 输出研究简报：3 个工具的输入输出 schema 草稿

3 Implement：生成完整代码

基于研究简报，MCP Builder 生成项目结构：

notion-mcp-server/

├── src/index.ts # Server 入口，stdio 传输

├── src/tools/ # 三个工具实现

│ ├── query-database.ts

│ ├── retrieve-page.ts

│ └── create-page.ts

├── package.json # 依赖 + 启动脚本

└── README.md # 使用说明

代码包含完整的 schema 定义、参数校验、错误处理、SDK 调用，直接能跑。

4 Test：启动并验证

MCP Builder 自动：

  • 执行 npm install && npm run build，编译通过
  • 启动 Server 进程，模拟 MCP 客户端连接
  • 逐个调用三个工具，传入测试参数，验证返回结构
  • 构造无权限、空 ID 等异常输入，验证错误返回
  • 全部通过，进入评估阶段

5 Evaluate：打分报告

评估脚本输出最终报告：

协议合规性：✓ 通过（JSON-RPC 2.0，stdio 传输正确）

工具完整性：✓ 3/3（全部按需求实现）

错误处理：✓ 覆盖（鉴权失败、参数缺失、API 限流）

文档完备性：✓ 完整（README + 工具描述）

综合评分：92 / 100

全程耗时：约 10 分钟。手动写至少要半天。

05 评估工具 /mcp-builder:evaluate 怎么用

工作流第 4 阶段会自动调用评估工具，你也可以手动触发，单独评估任意一个已存在的 MCP Server。命令就一条：

/mcp-builder:evaluate # 评估当前目录下的 MCP Server

⚠️ 前置条件：需要 ANTHROPIC_API_KEY

评估工具会调用 Anthropic 的模型对生成的 Server 做语义层面的检查（比如工具命名是否清晰、描述是否符合 MCP 最佳实践），所以需要配置环境变量 ANTHROPIC_API_KEY。没配置的话评估阶段会跳过语义打分，只做协议层面的硬性检查。

📊 评估报告包含的维度

协议合规性：JSON-RPC 格式、传输方式、消息序列是否符合 MCP 规范

工具完整性：声明的工具是否都实现、schema 是否正确、参数是否齐全

错误处理：异常输入、网络错误、鉴权失败是否有合理返回

文档完备性：README、工具描述、参数说明是否齐全

06 这些场景最值 + 和其他工具的关联

MCP 这边有两个方向：之前在 cc-switch 文章中介绍过 MCP 代理的用法，本文聚焦 MCP Server 的快速搭建。两者是 MCP 生态的两端：cc-switch 帮你管理怎么用 MCP，MCP Builder 帮你造 MCP。

① 内部系统接入 AI：把公司内部 API（审批、考勤、CRM）封装成 MCP Server，让 Claude 直接调用

② SaaS 工具集成：Notion、Linear、Jira、飞书、企业微信……批量造 Server，一键接入

③ 数据查询服务：把数据库、数据仓库封装成 MCP 工具，让 AI 自然语言查数据

④ 自动化工作流：MCP Server 作为可调用节点，串到 ECC 或其他 Agent 框架里

⑤ 学习 MCP 协议：读 MCP Builder 生成的代码，是理解 MCP 规范最快的路径

🔗 和 ECC 的关联

如果你用了 ECC，它的 MCP 集成能力正好可以接住 MCP Builder 做出来的 Server：MCP Builder 负责造 Server，ECC 负责在 Claude Code 里把多个 MCP Server 编排起来一起干活。一个管造，一个管用。

07 3 个常见疑问

Q1：需要什么基础才能用？

会写一句话需求就行。MCP Builder 把协议规范、SDK 选型、错误处理都封装在 4 阶段工作流里，你只需要说清楚"对接什么服务、要哪些工具、用什么语言"。当然，能看懂生成的代码、知道怎么调试，会让你更踏实。

Q2：支持哪些语言？

目前官方支持 TypeScript 和 Python 两种，对应 MCP 官方 SDK 的两个主要实现。提需求时说一句"用 TypeScript"或"用 Python"即可，工作流会按对应语言的 SDK 规范生成代码。

Q3：评估工具必须装吗？

不是必须的。前 3 个阶段（Research、Implement、Test）不依赖评估工具，能跑出可用 Server。但评估工具能帮你量化质量、检查出遗漏，还是建议装上。它跑语义打分需要有 ANTHROPIC_API_KEY。

最后的话

MCP 协议本身不算难，但手动搭一个 Server 要处理的琐碎事多：协议规范、工具注册、错误处理、测试验证，每一项都得自己啃。MCP Builder 把这几步重复的活编成了 4 阶段流程，你要琢磨的是"对接什么"，而不是"怎么对接"。

从提一句需求到跑通一个能用的 Server，大约 10 分钟。Anthropic 官方把它做成了 Skill，注册进 Claude Code 就能用。下次想给 AI 加能力，可以直接说一句需求，剩下让它跑一遍给你看。
