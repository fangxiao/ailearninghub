企业级 AI 编排平台——RuFlo 实战指南

100+ Agents · 210+ MCP 工具 · 跨组织联邦协作

GitHub 11.4k Stars · 原 Claude-Flow 已重命名 · 支持 Claude/GPT/Gemini/Ollama 多 Provider

痛点开篇

你是不是也遇到过这种情况：让 Claude Code 单干一个大项目，让它写前端、写后端、写测试、写文档，结果 Agent 在任务间反复横跳，上下文越来越长，最后要么 token 爆表，要么质量崩盘。单 Agent 撑不起复杂工程，这是当下每一个重度 AI Coding 用户都得直面的事实。

ECC 提供了命令库（见 ecc-everything-claude-code-公众号版.html），wshobson/agents 提供了开箱即用的 subagent 集合（见 wshobson-agents-生产级subagent集合-公众号版.html），但如果你想要的是企业级的多 Agent 编排 + 跨组织协作，那今天这篇主角 RuFlo 值得你认真看一遍。

01 RuFlo 是什么——原 Claude-Flow 重生

RuFlo 仓库地址是 github.com/ruvnet/ruflo，前身就是圈内小有名气的 Claude-Flow。项目作者把品牌从 Claude-Flow 重命名为 RuFlo，背后逻辑很清楚：这个平台早就不再只为 Claude 服务，而是一个Provider 无关的企业级 AI 编排系统，可以同时调度 Claude、GPT、Gemini、Cohere、Ollama 多家模型。

目前 GitHub 已收获 11.4k Stars，定位不是又一个"prompt 工具箱"，而是编排层（Orchestration Layer）。在你和各家大模型之间，它加一层调度大脑，把任务拆分给多个 Agent 并行或串行处理，再统一汇总结果。

💡 一句话定位

RuFlo = Claude Code 原生插件体系 + 多 Agent 编排引擎 + MCP 工具生态 + 联邦协作网络。它不替代 Claude Code，而是把 Claude Code 变成可被调度的一个执行节点。

02 三种安装方式——按场景选

RuFlo 提供三种主流安装路径，分别对应重度集成、轻量试用、MCP 协议接入三种使用姿势。三种方式不是非此即彼，可以组合使用。

方式一：Claude Code 插件市场（推荐重度用户）

在 Claude Code 内直接安装原生插件，享受 32 个原生插件带来的深度集成。命令分两步：

# 第 1 步：添加 marketplace

/plugin marketplace add ruvnet/ruflo

# 第 2 步：安装核心插件包

/plugin install ruflo-core@ruflo

方式二：CLI 向导（推荐新用户）

想先看看 RuFlo 长什么样，不想深度耦合到 Claude Code 里，用 npx 跑向导最简单：

npx ruflo@latest init --wizard

向导会引导你选 Provider、配置 API Key、决定要不要启用 Worker 和联邦模块，全程交互式完成。

方式三：MCP 接入（推荐已有 MCP 生态的用户）

如果你已经在用 Claude Code Router 这类多 Provider 路由工具（见 claude-code-router-公众号版.html），把 RuFlo 作为一个 MCP Server 接入最合适：

claude mcp add ruflo -- npx -y @claude-flow/cli@latest

注意包名仍沿用旧名 @claude-flow/cli，这是历史兼容遗留，不影响功能。

03 核心能力——四个关键数字

RuFlo 真正值钱的不在它有多少命令，而在这套编排系统背后沉淀的资产规模。四个数字记住就够：

32 个 Claude Code 原生插件

100+ 个可调度 Agent（覆盖前后端、测试、运维、文档）

210+ 个 MCP 工具（文件、搜索、数据库、浏览器全覆盖）

12 个后台 Worker（长任务、定时任务、并行执行）

这套组合拳最直接的体感是：以前你写一个全栈功能要手动切 5、6 次 Agent，现在RuFlo 用 GOAP 规划器自动拆任务，前端 Agent、后端 Agent、测试 Agent 同步开干，12 个 Worker 把长任务丢后台跑，主线 Agent 不阻塞。

💡 GOAP 规划器是什么

GOAP（Goal-Oriented Action Planning，目标导向行动规划）源自游戏 AI 领域。RuFlo 用它来把高层目标反向拆解成可执行 Action 序列，再分配给最合适的 Agent。和简单链式 prompt 相比，GOAP 能处理依赖关系、并行机会和回滚路径。

04 Agent 联邦——跨组织协作的关键

这一节是 RuFlo 区别于其他 Agent 框架的关键功能。所谓"联邦（Federation）"，换成大白话：不同组织、不同团队部署的 RuFlo 实例之间，可以让 Agent 互相通信、互相调用，类似联邦学习的思路，但搬到了 Agent 协作上。

举个例子：A 公司有个内部代码 Agent，B 公司有个部署运维 Agent，两边互不信任、不能共享代码。但通过 RuFlo 联邦协议，A 公司的编排器可以把"部署到生产"这个 Action 委托给 B 公司的 Agent 执行，只交换任务输入输出，不交换模型权重和源码。

"单组织内的 Agent 编排是 2025 年的事，跨组织的 Agent 联邦才是 2026 年的题。RuFlo 是目前把这件事说清楚、做出来的少数项目之一。"

当然，联邦功能对个人开发者有点远，但在企业团队、外包协作、跨厂商集成这些场景下几乎绕不开。如果你团队已经在用 Claude Code Router 做多 Provider 路由（详见 claude-code-router-公众号版.html），那么 RuFlo 联邦层是天然的下一步演进。

05 横向对比——RuFlo vs ECC vs wshobson/agents

这三个项目我都写过公众号文章（见文末引用），定位完全不同，不是替代关系，是互补栈。下表把核心差异列清楚：

维度 RuFlo ECC wshobson/agents
定位 企业级编排平台 命令库 + 速查手册 开箱即用 subagent 集合
核心资产 100+ Agents + 210+ MCP 工具 数百条 slash 命令 数十个细分角色 subagent
多 Provider ✓ Claude/GPT/Gemini/Ollama 仅 Claude Code 仅 Claude Code
编排能力 ✓ GOAP 规划器 + 12 Worker 无 无（手动调度）
跨组织协作 ✓ Agent 联邦 无 无
适用人群 企业 / 重度 AI 工程团队 个人开发者 / 速查 个人开发者 / 快速上手

一句话总结：ECC 是字典，wshobson/agents 是工具箱，RuFlo 是车间主任。三者可以叠加使用：用 ECC 查命令、用 wshobson 的 subagent 做单点任务、用 RuFlo 做整体编排。

⚠️ 避坑指南——上手前先看这五条

1. 包名混乱别踩坑。RuFlo 已重命名，但 npm 上部分包仍叫 @claude-flow/cli，MCP 命令里用的还是旧名。安装时认准 GitHub 仓库 ruvnet/ruflo，别被旧包名误导。

2. 多 Provider 别同时全开。RuFlo 支持 Claude/GPT/Gemini/Cohere/Ollama，但每个 Provider 都要单独配 API Key 和路由策略。第一次跑先只配一个 Provider，跑通再加。否则报错排查极痛苦。

3. 12 个 Worker 不是越多越好。Worker 数量取决于你机器 CPU 和各家 API 的并发限额。本地开发建议 2-4 个，云端部署再按需扩。

4. 联邦功能要先有信任边界。跨组织 Agent 通信涉及数据外发，务必先做任务白名单和输出过滤，别让对方的 Agent 直接拿到你的完整上下文。

5. 不要和 ECC、wshobson 二选一。这三个项目是互补关系，不是替代。强行只留一个会丢掉另外两边的资产。

✨ 写在最后

单 Agent 做不完的大工程，正在催生编排、联邦、规划器这些工具。RuFlo 不是唯一，但它是当前把这三件事一起做完的少数项目之一。

别把它当银弹，当车间主任就行。它不会替你写每一行代码，但确实能让多个 Agent 同时干活，还能跨组织调别的团队。装之前想清楚自己是不是真需要这么大的编排能力，个人小项目用单个 Agent 也许就够了。
