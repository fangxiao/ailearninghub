国内用户用 Claude Code 写代码，大概率遇到过这些问题：

❌ 官方 Claude Code 只支持 Anthropic 自家模型，国内访问体验差、延迟高

❌ API 价格昂贵，频繁迭代时 Token 消耗快，一个月轻松烧掉几百块

❌ 想用豆包、通义、DeepSeek 等国产模型，或者本地部署的开源模型，不知道怎么接入

❌ 不同 Agent 工具（Claude Code、Codex、Kilo Code）各自配一套，管理混乱

这些问题的核心矛盾是：AI 编程工具绑定了模型供应商。Claude Code 只能调 Anthropic 的 API，Codex 只能走 OpenAI，Kimi CLI 只能用月之暗面。想自由切换模型，就得各自改配置，非常麻烦。

一句话总结：Claude Code Router（简称 CCR）是一个本地模型网关，支持 10+ Agent、20+ Provider，让你用任何 AI 编程工具都能调用任意大模型。

01 CCR 是什么？本地模型网关

CCR（Claude Code Router）是一款开源的本地模型路由工具。它的核心思路很简单：在你的电脑上跑一个本地 API 网关，把所有 AI 编程工具的请求先收进来，再根据你的配置转发到对应的模型供应商。

这样一来，不管你用的是 Claude Code、Codex、Grok CLI 还是 Kimi CLI，它们看到的都是同一个本地地址（比如 http://localhost:8080），背后连的是哪家模型供应商，完全由 CCR 决定。

🔌 支持 20+ Provider：OpenAI、Anthropic、Gemini、OpenRouter、DeepSeek、SiliconFlow、Moonshot（Kimi）、Mistral、阿里百炼、豆包、通义、火山引擎……

🤖 支持 10+ Agent：Claude Code、Codex、Grok CLI、Kimi CLI、Kilo Code、OpenCode、Pi、ZCode……

🔄 任意组合：Claude Code 调用豆包、Codex 调用 DeepSeek、Kilo Code 调用本地 Ollama，Agent 和 Provider 自由搭配

之前写过 cc-switch（ccswitch搭配claude-code-01-公众号版.html）解决 MCP 代理管理问题，CCR 解决的是模型路由问题。两者互补，一个管 MCP 工具链，一个管模型调用链。

02 3 种安装方式，任选一种

CCR 提供了三种安装方式，覆盖不同使用场景。推荐新手用 Desktop App，老用户可以用 CLI 或 Docker。

⭐ 方式一：Desktop App（新手推荐）

图形界面，点点鼠标就能完成所有配置。支持 macOS、Windows、Linux。

步骤

1. 打开 GitHub Releases 页面，下载对应系统的安装包
2. 双击安装包，按提示完成安装
3. 首次启动，会引导你添加 Provider 和 Agent

# 下载地址 https://github.com/musistudio/claude-code-router/releases

方式二：CLI 命令行（开发者推荐）

全局安装 CCR 的 npm 包，通过命令行启动。适合需要脚本化部署或喜欢终端操作的用户。

# 全局安装 CCR CLI npm install -g @musistudio/claude-code-router # 启动可视化管理界面 ccr ui

执行 ccr ui 后，浏览器会自动打开管理界面，在网页里完成所有配置。

方式三：Docker 容器化（服务端部署）

用 Docker Compose 一键拉起，适合团队共享服务或服务器部署。

# 克隆仓库 git clone https://github.com/musistudio/claude-code-router.git cd claude-code-router # 一键启动 docker compose up -d --build

启动后访问 http://localhost:8080 即可管理面板。

💡 选择建议：日常开发用 Desktop App 或 CLI，体验最好；团队共享或服务器部署用 Docker，方便统一管理。

03 五大核心功能

CCR 的能力远不止"转个 API"。它是一个模型路由平台，下面拆开来讲。

① 智能路由切换：每个请求走最优路径

可以按 Agent 维度配置路由：Claude Code 的请求走豆包、Codex 的请求走 DeepSeek、Kilo Code 的请求走本地模型。也可以按模型级别细分，比如 Opus 走官方 API、Sonnet 走 OpenRouter 代理。

② 自动故障转移：一个 Provider 挂了不影响使用

为每个模型配置备用 Provider 队列。主 Provider 超时或返回错误时，CCR 自动切到备用线路，用户无感知。配合熔断器机制，持续失败的 Provider 会被暂时跳过。

③ Fusion 视觉：文本 + 图片混合能力

部分 Provider 支持多模态（视觉理解），但不同 Provider 的能力不同。CCR 的 Fusion 功能可以在支持视觉的 Provider 间自动切换，当你在 Claude Code 中发送图片时，自动路由到能处理视觉的模型。

④ MCP 集成：统一工具调用入口

CCR 内置 MCP 客户端，可以作为 MCP Server 接入各种 Agent 工具。配合 cc-switch 使用，MCP 工具链和模型路由链打通，凑成一套 AI 编程基础设施。

⑤ 用量统计与成本分析

实时统计每个 Provider、每个模型、每个 Agent 的 Token 消耗量和费用。支持设置月度预算预警，帮助你控制成本。

04 5 步快速上手

从安装到跑通第一个请求，只需要 5 步。以下用 Desktop App 为例，CLI 和 Docker 流程类似。

1 添加 Provider：配置你的第一个模型供应商

打开 CCR → 点 "Add Provider" → 选择预设（比如 SiliconFlow）→ 填入 API Key → 保存。CCR 内置了主流 Provider 的预设，Base URL 和 API 格式自动配置好。

2 启动网关：让本地代理跑起来

在 CCR 面板里点 "Start Gateway"，默认在本地 http://localhost:8080 启动。你可以在设置里修改端口。

3 配置 Agent：把 AI 编程工具指向本地网关

在 Claude Code 的 ~/.claude/settings.json 里，把 API 地址改成 CCR 的本地地址：

{ "env": { "ANTHROPIC_AUTH_TOKEN": "sk-ccr-local", "ANTHROPIC_BASE_URL": "http://localhost:8080" } }

4 设置路由：决定每个 Agent 走哪个 Provider

在 CCR 的路由配置里，添加一条规则：Agent 选 "Claude Code"，模型选 "sonnet"，Provider 选 "SiliconFlow"。这样 Claude Code 的所有 Sonnet 请求都会走 SiliconFlow。

5 开始使用：正常打开 Claude Code 即可

打开 Claude Code，正常对话、写代码。CCR 在后台默默把请求路由到你指定的 Provider。你可以在 CCR 面板实时看到请求日志、Token 消耗和费用统计。

05 适用场景：哪些人最需要 CCR

① 国内用户：切豆包/通义/本地模型：Anthropic 官方 API 国内访问不稳定，用 CCR 切到国内 Provider（字节豆包、阿里通义、百度千帆、月之暗面等），速度更快、价格更低。

② 多项目切换成本：不同项目需要不同模型。A 项目用 Sonnet 快速迭代，B 项目用 Opus 做复杂推理。CCR 可以按项目配置路由规则，不用每次手动改。

③ 成本控制：官方 API 贵的时候切到便宜的 Provider，需要高质量时切到强模型。CCR 的用量统计让你对每一分钱都清清楚楚。

④ 混合团队工具链：团队有人用 Claude Code、有人用 Codex、有人用 Kilo Code。CCR 统一网关，所有人共享同一套模型配置。

⑤ 隐私敏感场景：代码不想传到第三方 API，可以路由到本地部署的 Ollama 或自建模型服务，数据不出本机。

06 CCR vs cc-switch：管模型 vs 管 MCP

经常有人问 CCR 和 cc-switch 是什么关系。它们是互补工具，解决不同层面的问题：

对比维度 CCR (Claude Code Router) cc-switch
核心定位 模型路由网关 配置管理器
解决的问题 Agent 绑定模型，无法自由切换 手动改 JSON 配置繁琐易错
管理对象 Provider（模型供应商） Provider + MCP + Skills
核心能力 API 路由、故障转移、格式转换 配置切换、MCP 管理、Skills 安装
运行方式 本地 HTTP 网关 Tauri 桌面应用
搭配使用 cc-switch 管配置，CCR 管路由，形成完整方案

简单理解：cc-switch 是"配置管家"，CCR 是"交通警察"。cc-switch 帮你把配置写对、管好，CCR 帮你把请求按规则转出去、转对地方。两者可以独立使用，也可以搭配使用。

07 FAQ：3 个常见疑问

Q1：CCR 会增加延迟吗？

CCR 是本地转发，延迟增加在 5ms 以内，基本感知不到。真正影响延迟的是你选择的 Provider 网络质量。如果用国内 Provider，反而可能更快。

Q2：CCR 免费吗？数据安全吗？

CCR 是开源免费的（MIT 协议）。所有请求都在本地处理，API Key 只存储在你本地，不会上传到任何服务器。代理模式下，Provider 只能看到来自本机的请求。

Q3：支持自定义模型映射吗？

支持。你可以在 CCR 里自由定义模型映射关系，比如把 Sonnet 映射到 deepseek-chat，把 Opus 映射到 qwen-max，只要 Provider 支持这些模型 ID 就行。

最后的话

Agent 越来越多，可用的模型也越来越杂，同一个工具换模型、多个工具共用一套模型，来回调配置这件事本身就值得到解决。

CCR 把这些都收敛到一个本地网关：你只管告诉它每个 Agent 该走哪家模型，剩下的转发、切换、统计都由它来。加上 cc-switch 把配置一并收进面板，日常切换就变成托盘里点一下的事。
