别把答案埋起来——i-have-adhd 实战

让 AI 输出对 ADHD 友好，答案先行

AI 编程工具推荐 | 输出风格 Skill 实战

你有没有过这样的体验：问 AI 一个问题，它给你写了三段铺垫、五点分析、最后才在结尾的括号里悄悄给出那句"所以答案是 X"。

你盯着屏幕，眼睛扫过一遍又一遍，最后还是只能 ctrl+F 找"答案"两个字。

❌ "在我开始回答这个问题之前，我们需要先了解一下背景……"

❌ 一段 800 字的回答，关键结论藏在第 3 段第 4 句

❌ 读完一长串步骤，不知道下一步到底先做哪个

❌ 你只是想要个"是"或"否"，AI 给你写了篇小论文

这不是 AI 不聪明，是它默认的输出习惯，和普通人读信息的方式对不上。尤其对注意力容易飘走的人来说，比如 ADHD 患者，这种"答案埋到最后"的回答方式，基本就是劝退。

i-have-adhd 就是来解这件事的。它不复杂，10.1k stars，三行命令装上，AI 的回答方式立刻变得"先给结论、再讲怎么做、告诉你下一步干啥"。

一句话总结：i-have-adhd 是一个让 AI 输出对 ADHD 友好的 Skill，强制 AI "答案先行、分步骤、给下一步行动、不埋答案"，支持 Claude Code、Codex、Gemini CLI 三个主流 Agent。

01 i-have-adhd 是什么

i-have-adhd 是一个开源的 Skill，仓库地址是 ayghri/i-have-adhd，目前 GitHub 上 10.1k stars。它干的事只有一件：

让 AI 的回答方式变得"对注意力不友好的人也能用"。

它本质上是一个 Skill（如果你还不熟 Skill 是什么，可以看我们之前写的 anthropics/skills 官方技能库介绍，里面有完整科普）。Skill 类似于给 AI 加的一套"行为约束说明书"——装上之后，AI 在生成回答时会自动遵循这套规则。

i-have-adhd 的规则非常具体：第一句给结论、信息按步骤排、给一个明确的下一步行动、不要把答案藏在段落中间。听起来简单，但效果立竿见影。

📌 关键信息

• 仓库：https://github.com/ayghri/i-have-adhd

• Stars：10.1k

• 支持平台：Claude Code、Codex、Gemini CLI

• 激活命令：/i-have-adhd

为什么要专门为 ADHD 优化？因为 ADHD 不是"不聪明"，而是"注意力难以维持在枯燥信息上"。一段正常 AI 回答对一个普通人可能只是"啰嗦点"，但对 ADHDer 来说可能就是"读到第二段就走神、然后整篇作废"。i-have-adhd 的存在，本质上是把 AI 的输出重新排版成"注意力经济"友好的形态——而这其实对所有用户都是好事，谁不希望先看到答案呢。

02 安装方式：plugin marketplace + 可选常驻

i-have-adhd 通过 Claude Code 的 plugin marketplace 安装，两行命令搞定。

第一步：添加 marketplace

# 添加 i-have-adhd 的 marketplace 源 claude plugin marketplace add ayghri/i-have-adhd

第二步：安装 plugin

# 安装 i-have-adhd plugin claude plugin install i-have-adhd@i-have-adhd

装完之后，在 Claude Code 会话里输入 /i-have-adhd 就能激活。激活之后，本次会话内 AI 的输出就会自动按 ADHD 友好的规则来排版。

💡 可选：常驻模式

如果你不希望每次都手动输入 /i-have-adhd，可以开启常驻模式——让它默认生效。

# 创建一个空文件，i-have-adhd 就会常驻 touch ~/.claude/.i-have-adhd-always

这个文件存在时，AI 会默认遵循 ADHD 友好的输出规则，不需要每次手动激活。删掉文件就恢复默认行为。

除了 Claude Code，Codex 和 Gemini CLI 也都支持。安装方式类似，具体可以看仓库 README——核心都是把这个 Skill 装到对应 Agent 的 skills 目录下。

03 四大规则：答案先行 / 分步骤 / 给下一步 / 不埋答案

i-have-adhd 的全部秘密就四条规则，没什么花活儿，但每一条都正好对着"AI 默认输出习惯"的那些毛病下手。

1 答案先行（Answer First）

回答的第一句，必须是直接结论。不是"让我们先理解一下背景"，不是"这个问题很有意思"，而是用户问的那个"答案"。

❌ "这是一个很好的问题。在回答之前，我们需要先了解……"
✅ "答案是用 git rebase。下面解释为什么。"

2 分步骤（Step by Step）

操作类的内容必须拆成清晰的步骤，用编号列表，而不是把所有动作揉在一整段文字里。每一步只做一件事。

❌ "你需要先打开配置文件然后修改里面的 timeout 字段接着重启服务最后验证一下日志。"
✅ "1. 打开 config.yaml / 2. 修改 timeout 字段 / 3. 重启服务 / 4. 验证日志"

3 给下一步行动（Next Action）

回答的最后必须给一个明确的"下一步要做什么"。不是开放式建议，是具体的、可立即执行的下一步动作。

❌ "你可以根据实际情况灵活调整。"
✅ "下一步：在终端运行 `git rebase -i HEAD~3`，把第 2 条 pick 改成 squash。"

4 不埋答案（No Buried Answers）

关键结论不能藏在段落中间，也不能放在长篇分析的尾部。如果一句话是用户要的"答案"，它就必须出现在最显眼的位置——开头或独立成段。

❌ 一段 400 字分析的第 5 句才是答案
✅ 答案单独成段加粗，分析放后面

这四条规则合起来，本质上是把 AI 的回答从"作文模式"切到"工作模式"。作文讲究起承转合，工作讲究先把事说清楚。

04 实战对比：有 vs 无 i-have-adhd

口说无凭，直接看个对比。问题是一样的：

用户提问："我用 git commit 提交错了，怎么撤销最近一次提交但保留改动？"

🔴 没装 i-have-adhd 的回答：

Git 是一个分布式版本控制系统，由 Linus Torvalds 在 2005 年创建。它在软件开发中被广泛用于跟踪代码变更、协作开发以及管理项目历史。

在 Git 中，每次提交都会创建一个新的快照，这些快照组成了项目的提交历史。当你想要撤销提交时，Git 提供了几种不同的方式，包括 reset、revert 和 checkout 等。

对于你描述的场景——撤销最近一次提交但保留改动——可以使用 git reset --soft HEAD~1 命令。这会把 HEAD 指针回退一个提交，但保留工作区和暂存区的改动。

希望这个回答对你有帮助，如果还有其他问题欢迎继续提问。

🟢 装了 i-have-adhd 的回答：

✅ 答案：git reset --soft HEAD~1

这个命令会把 HEAD 回退一个提交，但保留你的代码改动在暂存区。

操作步骤：

1. 在终端执行 git reset --soft HEAD~1

2. 用 git status 确认改动还在暂存区

3. 修改 commit message 后重新 git commit

下一步：

现在去终端执行第一步，看 git log 确认最近一次提交已被撤销。

同样的信息量，第二种回答让你3 秒内拿到答案，30 秒内知道怎么做，立刻能动手。第一种回答你得先读完 3 段铺垫，再去第 3 段中间扒拉出那条命令。

这就是 i-have-adhd 的价值。它不是让 AI 变聪明，而是让 AI 输出的东西，更贴合人读信息的方式。

📊 输出对比一览：

维度 无 i-have-adhd 有 i-have-adhd
答案位置 第 3 段中间 第一句
前置铺垫 2 段背景介绍 无
操作步骤 揉在段落里 编号列表
下一步 "希望对你有帮助" 具体可执行动作
读到答案耗时 约 30 秒 约 3 秒

05 对比 Humanizer：都是输出风格类 Skill

写到这，熟悉我们之前文章的读者可能会想到另一个 Skill——Humanizer-zh。它俩都属于"输出风格调整"类，但解决的是完全不同的问题。

简单说：Humanizer 管"像不像人写的"，i-have-adhd 管"读不读得进去"。

对比维度 Humanizer-zh i-have-adhd
核心目标 去 AI 写作痕迹 让输出对注意力友好
解决场景 文章读着像机器写的 回答读着抓不住重点
改动层面 用词、句式、语气 结构、顺序、行动项
典型场景 公众号、营销文案 技术问答、操作指南
能否叠加用 ✅ 可以——Humanizer 改"语气"，i-have-adhd 改"结构"

如果想做更深度的"写作风格迁移"，比如让 AI 模仿某个特定博主的语气，可以看我们之前写的 Khazix-Skills 写作风格迁移。三个 Skill 正好各管一样：Khazix 管"像谁写的"，Humanizer 管"像不像人写的"，i-have-adhd 管"读不读得进去"。

💡 怎么搭配用

写公众号/营销文案 → Humanizer + Khazix
写技术文档/操作指南 → i-have-adhd
既要可读性又要人味 → 三个一起开

⚠ 避坑指南

坑 1：常驻模式开过头

.i-have-adhd-always 一开，所有会话都强制 ADHD 友好模式。但有些场景你其实需要 AI 写长文、做深度分析（比如让 AI 写一篇文章草稿），这时候答案先行反而会破坏文章结构。建议：日常会话常驻开，写长文场景临时删文件。

坑 2：以为它能让 AI 变聪明

i-have-adhd 只改输出格式，不改答案质量。如果 AI 本来就答错了，装上之后只是变成"第一句就告诉你错的答案"——错的更快了。复杂问题还是要靠 prompt 引导 + 多轮追问。

坑 3：跟其它 Skill 冲突

如果你装了多个输出风格类 Skill（比如 Humanizer），同时激活可能会出现规则打架——Humanizer 想要"自然口语化"，i-have-adhd 想要"答案先行加粗"。建议按场景切换，不要全开。

坑 4：Codex / Gemini CLI 安装路径不一样

claude plugin install 是 Claude Code 的命令，Codex 和 Gemini CLI 的安装方式不一样——别照搬命令，去仓库 README 找对应平台的说明。

✨ 写在最后

i-have-adhd 这个名字听起来像是"只为 ADHD 患者服务"，但其实它解决的是一个更普遍的问题：AI 默认那种"堆铺垫、埋答案"的输出方式，本来就不符合人看信息的方式。

先给答案、步骤编号清楚、下一步做什么一目了然，这些不本来就是该有的吗？

所谓 ADHD 友好，说白了就是对所有人都友好。
