# AI 工具公众号文章 · 写作规范

适用于 `aitools/` 下所有"xxx-公众号版"文章。新建文章前先读本文件。

## 1. 工作流（md → html）

- 源文件：`*_公众号版.md`，必须带 frontmatter：

  ```markdown
  ---
  title: 标题
  description: 一句话摘要（用于分享卡片）
  ---
  ```

- 生成 HTML：`bash build.sh <文件.md>`
  - 用 baoyu-markdown-to-html（modern 主题，主色 `#2C6E9B`）
  - 脚本会把 modern 主题写死的边框/引用色 `#E4B1A0` 统一替换成 `#2C6E9B`
  - 产物：同目录 `<同名>.html`
- 图片放 `diagram/` 或 `screenshots/`，用相对路径引用。
- 命名：`<主题>-公众号版.md` / `<主题>-公众号版.html`

## 2. 去 AI 化（生成 HTML 前必做）

基于 humanizer-zh 规则，先改 `.md` 源文件再 build。重点：

- 删填充/铺垫开场：「先说结论」「先给结论」「先说清楚」「先说为什么」等
- 去堆叠破折号（——）、机械加粗、**强行三段式分组**
- 去 AI 高频词：关键 / 核心 / 至关重要 / 格局 / 深化 / 增强 / 此外 / 值得注意的是 / 一言以蔽之
- 结尾不要用通用乐观收束（"未来可期""迈出重要一步"），改成具体体会
- 适当用"我"、混合长短句、加入真实体感（踩坑、第一反应）
- 信任读者，少手把手解释、少软化

## 4. 结构约定

- 开头：点题 + 交代与前篇关系（用链接回扣）
- 正文：分节；教程类用编号步骤
- 结尾固定两段：
  - `接着看：` 交叉链接同系列 2–4 篇（`.html` 后缀）
  - `下期预告：` 指向下一篇；该篇写完后回头把预告闭环
- 内部交叉链接统一用 `.html`，不要 `.md`

## 5. 内容事实校验

- 写真实存在的工具/仓库时，先核对 GitHub README 或官网，避免编造命令名与参数
- 对比类数据标注"基于 YYYY 年中快照"，并提示以官网当下文档为准
