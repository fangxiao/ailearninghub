01 一句话讲清 cc-switch 是什么

cc-switch 是一款专为 AI 编程 CLI 工具打造的桌面端配置管理器。简单说，就是把"手抠 JSON 改配置"变成"点一下鼠标"。

目前支持 7 款主流 AI 编程工具：

Claude Code · Claude Desktop · Codex · Gemini CLI · OpenCode · OpenClaw · Hermes Agent

技术栈用的是 Tauri 2（Rust 后端 + React 前端），开源免费（MIT 协议），GitHub 上 40K+ Star，作者更新很勤。

它管的东西比改 API 地址多得多——Provider、MCP、Skills、Prompt、用量统计，全收拢到一个面板里。

02 安装与基础配置详解

1 安装：支持全平台

cc-switch 支持 Windows、macOS 和 Linux。推荐用包管理器装，最省心。

macOS 用户

# 先添加仓库源 brew tap farion1231/ccswitch # 再安装 cc-switch brew install --cask cc-switch

Windows 用户

方式一：MSI 安装包

1. 打开 GitHub Releases 页面，下载 CC-Switch-v{版本}-Windows.msi。

2. 双击运行，按提示完成安装。如果弹窗没反应，右键 → 属性 → 勾选「解除锁定」。

3. 遇到 SmartScreen 拦截时，点「更多信息」→「仍要运行」就行。

方式二：便携版（免安装）

下载 CC-Switch-v{版本}-Windows-Portable.zip，解压到纯英文无空格路径，直接运行 CC-Switch.exe 即可，删文件夹就卸载。

Linux 用户

Debian / Ubuntu（.deb）

# 下载 deb 包（把 {版本} 替换成实际版本号，比如 v3.16.1） wget https://github.com/farion1231/cc-switch/releases/latest/download/CC-Switch-v{版本}-Linux-x86_64.deb # 安装 sudo dpkg -i CC-Switch-v{版本}-Linux-x86_64.deb # 有依赖问题的话执行 sudo apt-get install -f

Fedora / RHEL（.rpm）

# 下载并安装 rpm 包 wget https://github.com/farion1231/cc-switch/releases/latest/download/CC-Switch-v{版本}-Linux-x86_64.rpm sudo rpm -i CC-Switch-v{版本}-Linux-x86_64.rpm

通用 AppImage（全发行版）

# 下载 AppImage wget https://github.com/farion1231/cc-switch/releases/latest/download/CC-Switch-v{版本}-Linux-x86_64.AppImage # 赋予执行权限 chmod +x CC-Switch-v{版本}-Linux-x86_64.AppImage # 直接运行 ./CC-Switch-v{版本}-Linux-x86_64.AppImage

ArchLinux（AUR）

paru -S cc-switch-bin # 或 yay -S cc-switch-bin

2 添加 Provider：配置你的第一个供应商

启动软件后，点右上角的 "Add Provider" 按钮，进入配置界面。有两种选择：

① 用内置预设（新手推荐）

cc-switch 内置了 50+ 主流供应商预设，包括 Claude 官方、DeepSeek、智谱 GLM、Kimi、通义千问、阿里百炼、OpenRouter 等。选好预设后，填入 API Key，Base URL 自动填好，格式也帮你选好。

② 手动自定义（高级用户）

用私有代理或不在预设里的供应商，可以手动填写：

Provider Name: 给供应商起个好记的名字，比如"我的私有代理"
Base URL: 供应商的 API 地址。注意：Claude 官方地址不要带 /v1，第三方 OpenAI 格式必须带 /v1。
API Key: 从供应商控制台获取的密钥。
API Format: Claude 官方选 "Anthropic"，兼容 OpenAI 的选 "OpenAI Chat Completions"。
Default Model: 设默认使用的模型名。

3 启用与切换

配置完成后，点 "Enable" (启用) 按钮，cc-switch 会自动把配置写入对应工具的配置文件。

三种切换方式：

① 主界面一键启用：在供应商列表里，点目标卡片右上角的"启用"按钮。
② 系统托盘后台切：右键 cc-switch 托盘图标 → 悬浮到"Claude · 当前供应商"子菜单 → 直接点要切的供应商。一秒完成，连软件窗口都不用开。
③ 只换内部模型：编辑已启用的供应商，修改 Sonnet / Opus / Haiku 对应的模型映射。同一个 API 账号里切"小模型快打 / 大模型深推理"很方便。

验证切换？

终端里运行 `claude` 命令，输入 /model，直接显示当前调用的模型名称。

03 进阶能力

一键切换只是及格。cc-switch 真正有用的是下面这些功能。

本地路由与自动故障转移

这是 cc-switch 最实用的功能。开启"本地路由"后，cc-switch 在本地启动一个代理服务器（默认端口 15721），接管所有 AI 编程工具的 API 请求。

代理后面有一套自动处理逻辑：

• 格式转换：自动处理不同供应商 API 格式差异（Anthropic Messages vs OpenAI Chat Completions），不用操心底层兼容。
• 自动故障转移：主供应商 API 异常时，自动切到备用供应商队列，无感降级。
• 熔断器：某个供应商持续失败就"熔断"一段时间，避免无效请求堆积。
• 健康监控：实时显示每个供应商的响应状态、延迟和成功率。

开启后，Claude Code 的 settings.json 会自动改成指向本地代理：

{ "env": { "ANTHROPIC_AUTH_TOKEN": "PROXY_MANAGED", "ANTHROPIC_BASE_URL": "http://127.0.0.1:15721" } }

API 请求先走本地代理，主供应商挂了自动切备用的，不用手动干预。

MCP 服务器统一管理

MCP（Model Context Protocol）正在成为 AI 编程工具的事实标准，用来连接外部数据源和工具。但每个客户端的配置格式不一样，管理起来很繁琐。

cc-switch 提供了一个跨应用的统一 MCP 管理面板：

• 双向同步：配置可以同步到 Claude Code、Codex、OpenCode、OpenClaw 四款工具。
• 多种协议：兼容 stdio、HTTP、SSE 三种 MCP 服务器传输方式。
• Deep Link 分发：支持 ccswitch:// 专属协议，团队负责人可以一键分发统一配置。

Skills 一键安装与管理

Claude Code 的 Skills 生态很活跃。手动下载、解压、复制到 ~/.claude/skills 目录不仅繁琐，还不利于版本管理。

cc-switch 的 Skills 面板让这件事变得像用 npm 装包一样简单：

• 一键安装：输入 GitHub 仓库地址（owner/repo 格式），自动下载安装。
• 版本管理：对已安装的 Skills 进行版本控制和更新。
• 软链接同步：用软链接而非复制，确保多处 Skills 内容一致。
• 热门扫描：自动扫描 GitHub 上的热门 Skills 仓库。

用量统计与成本控制

团队或高频用户肯定关心一个问题：每天烧了多少 Token、花了多少钱。cc-switch 内置了精细的成本追踪：

• 实时消费视图：看每个 Provider 的实时 Token 消耗量和费用。
• 模型分级统计：区分 Opus / Sonnet / Haiku 的消耗，便于优化。
• 预算预警：设月度预算，快超支时自动提醒。
• 历史报表：生成日、周、月维度的成本报表，方便核算。

04 高频避坑指南

我搜集了大量真实用户反馈，总结出最容易踩的几个坑：

⚠️ 坑 1：切换后没生效

彻底关掉所有 Claude Code 终端窗口，完全退出 cc-switch 再重新打开。同时检查"设置-路由"中，是否勾选了"接管 Claude Code"。

⚠️ 坑 2：401 鉴权失败

1. 检查 API Key 有没有多余空格。
2. Claude 官方 API 的 Base URL 不要带 /v1，第三方 OpenAI 格式的 API 必须带 /v1。这是最常见的。
3. 确认 API Format 选项对不对。

⚠️ 坑 3：端口被占用

本地代理端口默认 15721，被其他程序占了的话，去"设置-路由"改个端口号，确保防火墙放行本地地址。

⚠️ 坑 4：模型名不匹配

"模型映射"里填的模型名必须是供应商实际支持的。报 404 或模型不存在，90% 是模型名写错了，去看供应商 API 文档找准确的模型 ID。
